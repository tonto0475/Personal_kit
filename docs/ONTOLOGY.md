# ONTOLOGY — (과제 이름) 지도

> [!abstract] 읽는 법
> - **유저가 볼 곳**: 확인할 것 → 0. 한눈에 → 만들 것 판정 → 1. README 문장 풀이 / **AI 가 볼 곳**: 2 ~ 9번
> - 2 ~ 9번은 말로 풀어 쓴다. 꼭 필요한 숫자(개수 · 줄 번호 · 바뀌는 폭 · 손계산)만 칸 끝 🔢 줄에 따로. 해당 없는 칸은 지우지 말고 왜 없는지 한두 줄
> - 근거 표시(줄 끝): README 과제 글 · 데이터 직접 센 것 · 명세 API 문서 · 담당자 담당자 답(시각) · 유저 유저 결정 · 코드 기존 코드 동작(업무 규칙 근거 아님) · 추정 짐작
> - 🔴 추정 줄에는 같은 Q 번호를 붙이고, 그 Q 가 «확인할 것» 에 있어야 한다. 답을 받으면 근거를 바꾸고 10번에 기록
> - 쉬운 말만 · 데이터 열 이름은 그대로 쓰고 옆에 뜻 · 콜아웃 안에서 표 앞 줄이 글이면 빈 줄(«>») 하나를 둔다(없으면 표가 글로 깨진다)
> - 채운 예시: docs/examples/ONTOLOGY_ref_1.md(데이터 과제) · ONTOLOGY_ref_2.md(데이터 없는 서비스 과제) · 절차: $ontology

> [!danger] 확인할 것 — 질문은 유저가 직접 · 위에서부터
> | 번호 | 단계 | 확인할 것 | 답에 따라 바뀌는 것 | 상태 | 받은 답(요지) |
> |---|---|---|---|---|---|
> | Q1 | 1 쉬움 | (질문 문장이 아니라 확인할 항목) | (말로 — 숫자 폭은 8번 🔢 에) | ⬜ | |
>
> - 1단계(업무 흐름 · 사실 · 데이터의 뜻)를 먼저, 그 답을 듣고 2단계(세는 기준 · 판단)로 · 데이터로 먼저 알 수 있는 건 «먼저 직접 확인» 이라고 적는다
> - 묻는 요령: 한 번에 한 가지 · 추천을 붙여 «예» 로 답할 수 있게 · «모르겠다» 도 답으로 받는다(그럼 두 기준을 나란히 보여 준다)
> - 유저가 정할 것(화면 · 범위)은 «— 유저가 정함» 을 붙인다 · 받은 답은 요지만 여기에, 원문은 docs/INTERVIEW.md
> - 상태: ⬜ 대기 · 📨 보냄 · 🟢 답 받음 · ⏸️ 보류 · «답에 따라 바뀌는 것» 이 비면 묻지 않는다

> [!summary] 0. 한눈에 보기
> | 항목 | 내용 |
> |---|---|
> | 누가 쓰나 | |
> | 무엇을 하나 | |
> | 최종 결과 | (무엇을 · 어떤 단위 · 어떤 형태 — 숫자가 아니면 «서비스» 처럼) |
> | 누구와 맞추나 | (담당자 · 어떤 사람인지 한 줄) |
> | 아직 모르는 핵심 | (Q 번호) |
> | 가장 큰 함정 | (데이터 과제면 필수 — 같은 대상이 두 줄 · 붙일 열이 없음 · 분모 착각 등) |
> | 지금 상태 | 확인할 것 N개 중 답 받음 M개 · 만들 것 판정 K개(⭐ · 🟢 · 🟠 · 🔴) |

> [!tip] 만들 것 판정 — 답을 받을 때마다 고친다
> | 항목 | 판정 | 이유(쉬운 말) | 근거 |
> |---|---|---|---|
> | | ⭐ 필수 / 🟢 권장 / 🟠 과설계 우려 / 🔴 하면 안 됨 | | |
>
> - ⭐ 필수 = README · 담당자가 꼭 요구 / 🟢 권장 = 핵심 흐름을 살리고 비용이 작음 / 🟠 과설계 우려 = 요구 근거가 없음 — 담당자가 원하면 그때 / 🔴 하면 안 됨 = 규칙 위반 · 요구와 반대(🔒 개인정보 · 비밀값은 늘 여기)
> - 🟠 는 지우지 않고 «왜 안 했나» 로 남긴다 — 담당자와 범위를 합의할 때 그대로 쓴다

> |---|---|---|---|---|
> | | | (README · 데이터 열 · 담당자가 같은 뜻으로 쓰는 다른 이름) | (파일 · 열 이름) | |
>
> - 🔢 (개수)

> [!note] 3. 구별 기준 — 무엇이 같으면 같은 것인가
> - **(대상)** 은 (열 + 열) 이 같으면 같은 것이다. 데이터에서 실제로 겹치는가 · 겹치면 어떤 모양인가 (근거)
> - 🔢 (겹친 줄 번호)

> [!info] 4. 정보 — 대상 하나를 설명하는 값
> | 대상 | 정보 | 데이터 열 | 모양 · 범위(말로 — 단위 먼저 · 시간대 표시 여부) | 근거 |
> |---|---|---|---|---|
> | | | | | |
>
> - 🔒 개인정보 · 비밀값 열은 «쓰지 않음» · 단위가 섞였으면 따로 적고 확인할 것으로
> - 🔢 (값 종류별 개수)

> [!tip] 5. 연결 — 대상끼리 어떻게 이어지나
> | 시작 | 연결 | 끝 | 하나에 몇 개 | 무엇으로 잇나 | 시점 | 근거 |
> |---|---|---|---|---|---|---|
> | | | | (하나 / 여러 개 / 모름) | | (시간 따라 바뀌면 어느 시각 기준인가 · 상관없으면 «상관없음») | |
>
> **최종 결과까지 가는 길**
> - **1.** (데이터 파일 · API) → (대상)

> [!warning] 6. 경우 — 값이 될 수 있는 것
> | 대상 · 정보 | 경우 | 데이터에서 알아보는 법 | 나중에 바뀌나 · 무엇이 바꾸나 | 근거 |
> |---|---|---|---|---|
> | | | | (안 바뀌면 «바뀌지 않는다») | |
>
> - 빈칸 · 이상한 값도 경우 하나로 센다 · «모름 · 처리 중 · 보류» 같은 중간 경우가 나중에 무엇으로 바뀌는지가 자주 정답 자리다
> - 🔢 (경우별 개수)

> [!abstract] 7. 규칙 — 데이터에 대해 늘 지켜야 하는 것
> - **1.** (규칙 한 문장) [근거] — 확인: (테스트 이름 · ADR 성공 기준)

> [!success] 8. 계산 — 결과 숫자를 만드는 식
> - **(계산 이름)** = (위 — 무엇을 세나) ÷ (아래 — 무엇으로 나누나)
> - **순서**: (빼는 것 → 한 줄로 정리하는 것 → 붙이는 것 → 세는 것)
> - **나누는 수**: «줄 수» 인가 «대상 수» 인가 · 검사한 수인가 투입한 수인가 · 합칠 때 비율의 평균인가 합계의 비율인가
> - **같이 보여 줄 숫자 · 맞춰 볼 숫자**: (담당자 손계산 · 작은 표본을 손으로 센 값 — 표본 파일은 tests/fixtures/)
> - 🔢 (기준에 따라 바뀌는 폭 · 표본 손계산 값)
