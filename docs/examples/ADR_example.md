# ADR — 주문 API 안정성 개선 결정 · 진행 문서

> [!abstract] 한 줄 요약
> 주문 API 조회 · 저장을 안정화하는 과제의 결정 정본. 유저 · 구현자 · 검증자는 섹션 번호(1-1 …)로 소통한다.

> [!tip] 읽는 법
> - 섹션 = 기능 · 작업 하나. 블록 8개: 수정 범위 · 목표(개요) · 성공 기준 · 배경 · 논의 내용 · 결과 정리 · 검증 기록 · 코드 개선 제안
> - 수정 범위: 승인 전 주황(🟠) → 유저 답에 «승인» 이 오면 초록(🟢). 1-1 은 승인된 모양, 1-3 은 승인 뒤 범위 밖 파일이 생겨 다시 주황이 된 모양
> - 성공 기준: C 번호마다 → 검증 행. 민감(1-1 · 1-3)은 다섯 칸, 저위험(1-2)은 간단판
> - 줄 상태: 🔴 논의 필요 · 🟢 논의 완료 · ⏸️ 보류(아래 → 이유). 결정 아래 «→ 버린 안», 뒤집힌 옛 결정 끝에 «→ N회차에서 바뀜»
> - 회차: «작업 후» 항목으로 구현이 다시 시작되면 옛 블록을 옮기지 않고 그 아래에 **«논의 내용 · N회차» 블록을 새로** 만든다. 회차마다 색을 따로 판정한다(1-1 이 3회차까지 간 예시 — 끝난 1 · 2회차는 초록, 진행 중인 3회차는 빨강)
> - 상자 색: 🔴 줄 · 미검증이 하나라도 있으면 빨강(제목 끝 🔴), 없으면 초록(🟢)
> - 진행 표 기호: ⬜ 대기 · 🔄 진행 · 🟢 완료 · 🔴 논의 필요 · ⏸️ 보류 · ➖ 해당 없음

> [!abstract] ❇️ 목표
> 외부 주문 API 가 느리거나 끊겨도 화면이 멈추지 않고, 실패를 사용자에게 알린다.
> - **문제**: 외부 API 가 응답하지 않으면 화면 새로고침이 끝없이 기다린다
> - **원인**: 외부 호출에 대기 한도가 없다
> - **만들 것 / 안 만들 것**: 대기 한도 · 재시도 · 실패 응답 / 캐시 · 비동기 큐는 안 만든다
> - **제약**: 외부 API 주소 · 키는 바꿀 수 없다

> [!abstract] ❇️ 목표
> 결제가 늦거나 재시도돼도 주문은 한 번만 생기고, 결제 결과를 모를 때 주문을 잘못 취소하지 않는다.
> - **문제**: 결제 요청이 timeout 나면 같은 주문이 두 번 생기거나, 결제는 됐는데 주문이 취소된다
> - **원인**: 재시도 때 새 요청 번호를 쓰고 timeout 을 «실패»로 처리한다 · 주문 표에 중복 금지 설정이 없다
> - **만들 것 / 안 만들 것**: 요청 구별 키 · 중복 금지 설정 · «확인 중» 상태와 나중 확인 / 결제 서비스 쪽 변경 · 환불 처리는 안 만든다
> - **제약**: 결제 서비스의 응답 모양은 바꿀 수 없다
