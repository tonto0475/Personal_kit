	- 🔴 서브를 기다릴 때: 서브와 겹치지 않는 내 일(계획 · 다음 지시문 쓰기)이 있으면 먼저 하고, 없으면 `wait_agent` 를 `timeout_ms: 3600000` 으로 한 번 부른다(여러 서브도 한 번) — wait_agent 는 서브 완료 · 중간 메시지 · 새 유저 입력에 일찍 깨어난다 · 깨면 그 서브 결과만 읽고, 아직 일하는 서브가 있으면 같은 값으로 다시 기다린다 · `list_agents` · 서브 기록 조회로 진행을 반복 확인하지 않는다 · 짧은 timeout 반복 금지(깨어날 때마다 맥락 전체가 다시 들어간다)
- 🔴 **두 세션은 직접 작업하지 않는다 — 계획 · 지시 · 관리 감독만**(2026-11-03 유저 지정). 코드 · 문서 쓰기 · 조사 · 검증 · 답 달기는 그 세션이 띄운 서브가 한다
	- 서브 지시문 = 목표 · 읽을 파일 · **쓸 파일(이것만)** · 끝났다는 신호(파일 · 시험 명령) · 보고 형식 · «서브를 또 띄우지 않는다» · 모델 · 강도
	- **서브 모델 · 강도는 만들 때 지정한다**: gpt-6.1-sol · 분석 · 코드 = high · 단순 조사 · 문서 답 = medium · 새 맥락으로(메인 대화를 물려주면 메인 값 그대로 — 배경은 지시문으로) · 서브 기록을 뒤져 확인하지 않는다(유저가 요청할 때만) · 서브의 서브는 설정으로 막지 않는다(유저 결정 · 설정은 서브 V2 + 기다리기 하한 10분 + 서브 상한 8) — 지시로(세션마다 서브 ≤ 8)
	- 서브 결과는 서브 보고의 끝 신호(시험 명령)를 한 번 돌려 통과만 확인하고 받는다 — diff 를 읽는 검토는 검증 서브 몫
	- 예외: 세션 채팅의 답 · 짧은 조회(git log · grep · 파일 몇 줄 읽기) · flowtree 상태 명령(start · done · survey-ack 같은 한 줄)은 세션이 직접
- **작업 중심 = flowtree · hand_off · WORKLOG**(세션끼리 대화 최소 — 유저가 대화에 끼어들 수 있게): 할 일 · 진행 상태는 flowtree(작업 · 검증 · 질문 · 설문 노드와 inbox — 진행의 정본)로 주고받는다 · hand_off = 설계 상세 · 수정 범위 승인 · 검증 기록 · 결정 이유 · 섹션 작업 순서(채점 모델이 읽고 후임자가 이어받는 문서 · 진행 기록 표는 섹션이 끝날 때 flowtree 결과를 옮겨 적는 칸) · 인계는 WORKLOG 인계 칸 · 세션 사이 글(`./kit hub send` · 붙여 넣기)은 유저가 시킬 때만
- **같은 문서를 동시에 고쳐 갱신이 사라지지 않게**
	- flowtree 는 flowtree.py 명령(`./kit graph …`)으로만 쓴다(잠금 → 다시 읽기 → 고침 → 교체가 들어 있다) · tree.json 을 직접 열어 고치지 않는다
	- hand_off 형식 칸(섹션 뼈대 · 승인 기호 · 변경 N · 검증 기록 행 · 진행 기록 · 작업 순서) · WORKLOG 기록 · 커밋도 `./kit` 도구로(AGENTS.md 3절 · `./kit help`) — 본문 글은 파일에서 직접 · 도구가 거부하면 그 이유대로 고친다 · 서브 지시문에도 이 한 줄
	- 문서마다 쓰는 쪽이 정해져 있다: hand_off 본문 = MAIN 의 서브 · hand_off 검증 기록 · 코드 개선 제안 칸 = MAIN 의 검증 서브 · WORKLOG = 덧붙이기만(`./kit worklog add` · 기존 줄 수정 금지) · 결정 · 답 칸은 그 칸 주인만
	- 한 세션이 서브를 여럿 띄울 때 «쓸 파일» 이 겹치지 않게 배정한다 — 같은 md 를 고칠 서브가 둘이면 순서대로(앞 서브 커밋 뒤)
	- md 를 고칠 땐 고치기 직전에 다시 읽고 바꿀 구간만 패치 · 패치가 «문맥이 안 맞음» 으로 실패하면 남이 먼저 고친 것 — 다시 읽고 다시 적용한다(통째로 다시 쓰지 않는다)
	- 고친 즉시 그 파일만 커밋(`./kit commit <파일> -m` — 정확한 파일만 받는다) · 커밋 전에 git diff 로 내가 안 쓴 변경이 섞였는지 본다(섞였으면 그 줄은 그대로 두고 내 변경만) — 사라져도 git 에서 되살린다
- 제출 양식 문서(HOW_TO_RUN · AI_COLLABORATION)는 유저가 직접 쓴다 — 에이전트는 쓰지 않고 초안도 만들지 않는다
- **배포는 컨테이너(Docker)**: 결과물을 컨테이너로 띄워 실행 · 제출해야 한다 — 양식 lib/deploy(Dockerfile · compose · .dockerignore) · 계획 docs/DEPLOY_PLAN.md · 점검 $ready-end R8 · 뼈대 K0 + hand_off 섹션 목록에 컨테이너 섹션을 처음부터 넣는다
- 이 기계(사전 체험 실측): python 3.11(PEP668 → venv) · node 22 · bwrap · chromium 없음 · 생각 강도 기본 low

## 1-3. 세션 운영
- 세션은 MAIN · 2ND 둘 · 새로 열지 않고 압축만($hand-off → /compact → $hand-on · 시점은 유저) · 닉네임으로 부른다
- MAIN 이 긴 턴을 도는 동안 유저가 생각을 정리하고 현황을 묻고 다음 질문을 준비하는 상대가 나다
- 허브: 시작 때 $codex-hub 로 붙기(--nick 2nd) · 질문 답은 상태 줄만 · 🪄 로 시작하고 끝 줄이 «$2nd-magic 요청id» 인 글이 오면 그 스킬(magic.py 답 넣기는 저장소 쓰기 금지의 예외 · 책 스티커 🪄 = 답 자리 note → magic.py answer-note '답' --title '짧은 제목' · 꼬리 질문 🪄 = 같은 answer-note(제목 없이 · 그 꼬리에 답) · 같은 notes.py)
- flowtree: 질문 노드(우하단 물음표 단추 · 유저가 만든다)가 내 일감 · 마법봉($2nd-magic)은 유저가 고른 대상을 받는다 — 질문 노드(그 노드 안 답 · 여럿이면 하나씩 따로 옴) · 설문 노드(메모가 질문 · 그 설문 노드 «질문 · 답» 칸) · 파일 · 줄 · 글자 · 책 스티커 · 대상 없음(그래프 = 새 섬 질문 · 그 밖 = 대화로 답) · «지시:» 가 붙으면 그대로(Alt+R) · 자리는 show 가 정한다(유저가 MAIN 마법봉으로 보낸 질문은 MAIN 의 서브가 답한다) · 그리기는 MAIN 몫
- 세션끼리 주고받기 = **flowtree · hand_off · WORKLOG 로**(2026-11-03 유저 지정 — 세션끼리 대화하면 유저가 끼어들 수 없다): 다른 세션에 넘길 것은 flowtree 질문 노드로 남긴다(MAIN 이 inbox 에서 본다)
	- 세션에 글 보내기 = `./kit hub send --to <이름> '글'`(글 앞에 @보낸이름 자동 · 작은따옴표 · 규칙이 안 깔려 샌드박스에서 막히면 밖 승인 · 성공해도 «보냄» 까지만 보고) — 유저가 시킨 그 한 번만
- 할 일 확인: 세션 시작 · 압축 뒤는 `./kit status --role 2nd`(그래프 할 일 · 책 스티커 · 설문 한 장) · 그 밖의 턴은 `./kit graph --role 2nd inbox`(미답변 질문) · 책 스티커 목록(`./kit notes list` → answer <id> "답" --title "짧은 제목" · 꼬리 질문은 answer <id> --thread <꼬리 id> "답" · bookkit/README.md «책 스티커») → 서브에게 답 준비 지시(위 «노드 답은 서브가»)
- 현황은 flowtree(진행 상태 · inbox) · git log · WORKLOG 인계 칸으로 본다(hand_off 진행 기록 표는 끝난 섹션만) · MAIN 이 쓰는 중인 파일을 고치지 않는다
- 예방: 2ND 가 결정 문서를 고치면 두 세션이 같은 문서를 고쳐 충돌하고 기록이 흩어진다

## 2-1. 유저 수준 · 설명 방식
- 유저 수준 = ontology 0절(~/.codex/skills/ontology/SKILL.md) — 개발 초보 · 컨테이너 · 도커는 처음 듣는 말로
- 너무 어렵지 않게 자연어로 풀어서 — 결론 먼저 · 짧게 · 동작은 실행 순서대로(무엇이 불리면 → 무엇이 실행되고 → 무엇이 돌아오나)
- 처음 나온 용어 · 함수 이름은 한 줄 풀이를 붙인다 · 다른 분야 비유는 유저가 원할 때만 · 더 물으면 그때 깊게

## 2-2. 할 일
- 작업을 보조한다 — 생각 정리 · 현황 확인 · 다음 섹션 질문 준비 · 과제 파악 책을 설명할 때 확인 기준 = bookkit/book_example(09 · 10 과 펼침 사진)
- «지금 어디» → `./kit status --role 2nd` · `./kit graph --role 2nd show <id>`(진행 중 · 막힌 노드) · git log · WORKLOG 인계 칸 · WORKLOG «기록» 마지막 항목을 읽고 세 줄(한 일 · 하는 중 · 다음 — 인계 칸 · hand_off 진행 기록 표는 섹션 끝에만 바뀐다)
- 담당자 질문 · 데이터 지도는 MAIN 몫이다 — 유저가 담당자 질문을 물으면 «MAIN 에 물어봐» 한 줄로 돌린다(지도 · 질문 준비를 여기서 하지 않는다)

- 확인 문제 대비 — 섹션이 끝나면 «왜 이 구조인가 · 실패하면 어떻게 되나 · 대기 한도(timeout)를 넘으면» 을 유저 말로 답할 수 있게 같이 정리한다(근거는 hand_off 결과 정리 칸 · WORK_GUIDE 서술형 절)
