# P — 준비판: 당장 구현 가능한 틀을 그래프로 (A3 · A2 · 지휘)

**언제**: `$ontology` 1-0 ⑨ — A2 · A3 이 계약 PASS · «이어서 지도» 끝 신호를 낸 뒤(steps 가 raw 였으면 clean 뒤). 집필 · 2차판과 나란히 돌고 2차판을 늦추지 않는다 · 보고는 1-9 뒤
**읽을 것**: `~/.codex/skills/graph/SKILL.md` 1 · 3절 · 예 `docs/examples/graph_example.md` · 지도 «확인할 것» · `reqs.json`
**쓸 것**: A3 = `<책>/work/graph_plan.md` · flowtree 작업 · 검증 노드 · `docs/hand_off.md` 뼈대 / A2 = flowtree 설문 노드만 · 커밋하지 않는다(지휘가 승인 때)

## A3 — 계획표 · 그래프 초안 · hand_off 뼈대
1. `python3 skeleton/plan.py --task <키트>/task_copy --book <책>` → `skeleton/out/plan.json` · `plan.md`
2. 지도 «확인할 것» 을 다시 읽고 항목을 세 칸으로(바로 · 설문 하나면 됨 · 담당자 답 필요) → `work/graph_plan.md`(표 — 항목 · 칸 · 이유 · 설문 주제 · 작업 제목 + 맨 아래 «질문 목록» 확인할 것 번호)
3. 섹션0 틀을 `fill` 로 채운다 — 틀 작업 4칸 → 그 작업의 검증 칸(그래프 명세 3절 · 넘치는 작업은 섹션1 틀) — 첫 조각 = 입력 → 처리 → 출력 한 바퀴
4. `docs/hand_off.md` — 작업 개요(뼈대 파일 · 함수 표 · 섹션 목록) · 진행 기록 표 · 섹션 작업 순서 한 줄 · 섹션 1-1 뼈대(수정 범위 = 바로 · 설문 칸 작업의 파일 · 함수 · warning 🟠 · 목표 · 성공 기준 C 번호 + 검증 행)
5. 끝 신호: «준비판 노드 — 채운 틀 작업 N · 검증 N · 설문 주제 N · 질문 목록 N» 한 줄

## A2 — 설문 문항(지휘의 `followup_task` «준비판 설문 — graph_plan.md» 를 받으면)
1. 맨 앞: 틀 설문 칸 `s0-t1-s1` 을 `fill` 로 «이 범위로 시작할까?» — 선택지 «이 범위로 시작» · 범위를 줄인다 · 범위를 고친다 · 추천 1 · `--detail` = 범위에 든 것 · 빠진 것 · 시작하면 무엇을 먼저 보나를 쉬운 말로
2. graph_plan.md 의 설문 주제마다 그 작업의 틀 설문 칸에 `fill` — 재료 = 책 «말하지 않은 곳» S · 숨은 요구 H · 추천안 · 이유까지 · 전체 3 ~ 5개(그래프 명세 3절 «설문 문체»)
   - 🔴 설문의 선택지 · 배경(`--detail`) · 추천 이유에 항목 번호 · id · 약어를 쓰지 않는다 — 내용을 풀어 짧은 문장 여럿으로(무엇이 걸려 있나 · 고르면 무엇이 달라지나 · 예시). 유저가 그 노드만 읽고 결정할 수 있어야 한다 · 문서 링크는 설명을 대신하지 못한다
3. 끝 신호: `flowtree.py --role main check` «점검 정상» + «설문 N개(id)» 한 줄

## 지휘
- 차례: A3 끝 신호 → A2 에게 `followup_task` → A2 끝 신호 → 유저에게 한 줄(«그래프 준비판 — 작업 N · 설문 N · 맨 앞 설문부터»)
- A1 이 뒤에 더한 확인할 것에 걸리는 바로 칸 작업은 A3 에게 `hold <작업> "번호 답 대기"`
- inbox «설문 결정됨» — 맨 앞 설문:
  - «이 범위로 시작» → hand_off 1-1 수정 범위 `> 🚹` 칸에 «승인(설문 <id> «이 범위로 시작»)» 을 옮겨 적고 success → 커밋 · WORKLOG 섹션 시작 커밋(main 1-5) → `survey-ack`
  - 줄인다 · 고친다 → 메모대로 범위를 고치고 `survey-ack` → 새 설문 «이 범위로 시작할까?»(그 답까지는 구현하지 않는다)
- 설문이 붙은 작업은 그 설문이 결정된 뒤 시작 · 나머지 설문은 `$graph` 논의 반영
- 준비판 뒤 A3 은 그대로 섹션 계획 서브(plan)가 된다 — 구현은 새로 띄운 impl 이 맡는다(`main` 1-7 표) · A2 는 test
