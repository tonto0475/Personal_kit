## 1-3. 세션 운영
- 세션은 MAIN · INSP · 2ND 셋 · 늘리지 않는다 · 새로 열지 않고 압축만($hand-off → /compact → $hand-on · 시점은 유저)
- 설계와 구현을 한 세션이 한다(계획 대화의 이유 · 버린 안 · 담당자 답의 뉘앙스를 잃지 않게) → 맥락이 빨리 차니 섹션이 끝날 때마다 결정 칸 · WORKLOG 인계를 채운다
- 세션은 닉네임으로 부른다 · UUID 가 필요하면 whoami.py name 이름(같은 이름이 둘 이상 · 0개면 추측하지 말고 유저에게) · 같은 이름으로 새 세션 · 서브를 만들지 않는다
- 세션끼리는 codex queue --thread <UUID> 로 보낸다(이름으로 보내면 실패한 실측) · 성공해도 «큐 등록» 까지만 보고(읽었다는 뜻 아님) · 받는 쪽이 턴을 도는 중이면 그 턴이 끝난 뒤 들어간다(추정 · 통신 시험으로 확인)
- 검증 왕복
	1. 단계를 커밋 → INSP 에 codex queue(작은따옴표)로 «$decision-work verify 섹션번호 · 단계 · 범위(섹션 시작 커밋..이번 커밋) · 볼 파일»
	2. INSP 회신(«검증 끝 — 커밋 해시 · 불일치 N건») → 그 커밋을 git show 로 읽고 재현 스크립트를 직접 다시 돌려 판정($decision-work 4절)
- 예방: 세션이 늘수록 같은 파일을 동시에 고쳐 충돌하고 기록이 흩어진다

## 1-4. 구현 단위 — 위험도로 나눈다
- 섹션 제목에 저위험 / 민감 표시

## 3-5. 재현 스크립트는 파일로

- 재현(RED)은 기대값이 틀려 failed 한 것만 · 준비 오류(error — import · 픽스처 · 오타)는 재현이 아니다 → 테스트부터 고친다
- 재현 테스트엔 «예상된 실패» 표시(xfail · raises=AssertionError · strict=True · CODE_RULE 13절) · 민감 섹션 버그는 재현 커밋(표시) → 수정 커밋(표시 뗌) · 마지막 커밋은 반드시 통과
- INSP 의 «통과» 를 그대로 믿지 않고 직접 다시 돌려 판정(실제 문제 / 맥락 부족 오탐 / 해석 차이)

## 3-6. 형제 전수 점검 · 회귀 범위
- 버그 하나를 고치면 형제를 전부 확인: 같은 사전의 다른 키 · 그 함수의 모든 호출부 · 다른 분기 · 대칭 쌍의 반대쪽 → 보고에 형제 목록과 판정
- 회귀 범위 = 고친 층 + 그 층을 쓰는 위 층(외부 연결 · DB → 업무 처리 → 화면) + 고친 기능을 부르는 다른 경로
- 같은 결과를 내는 경로가 둘 이상이면(화면 표 · CSV 등) 필수 칸 목록을 테스트에 하나로 두고 모든 경로가 다 내는지 단언
- 예방: 하나 고치고 쌍둥이를 놓친다

## 3-7. 테스트 조건을 느슨하게 만들지 않는다
- 테스트를 지우거나 조건을 느슨하게 바꿔 통과시키지 않는다 · 기대값이 바뀐 건지 코드가 틀린 건지 먼저 가린다
- 즉석 스크립트도 기존 테스트 · 문서에 적힌 함정(멈추는 호출 · 화면 없는 환경)을 먼저 찾아 쓴다

## 3-8. 회귀는 관련 부분부터 · 전량은 지시 한 번만
- 관련 테스트만 지목해 돌린다(pytest 는 폴더 지정)
- 전량은 «전량 돌릴까?» 제안만 · 유저가 시킨 그 한 번만 유효(지난 사례로 다음에 스스로 돌리지 않는다)
- 전량을 안 돌렸으면 보고에 «미검증 범위 있음» · 판정은 결과 문자열 + 종료코드 · 시간에 따라 바뀌는 테스트는 실제 경과 시간에 기대지 않는다

## 4. 부른 직후 마지막 — 다른 세션과 queue 통신 시도
- $main 으로 불렸을 때 맨 끝에 한 번(유저가 «통신 시험» 이라고 해도 이것) · 압축 뒤 이 파일을 다시 읽을 때는 하지 않는다
- INSP · 2ND 마다: python3 ~/.codex/skills/ready-start/whoami.py name <이름> → UUID
	- 0개 · 둘 이상이면 보내지 않고 «<이름> 아직 안 뜸(또는 이름 겹침) — 뜬 뒤 '통신 시험'» 한 줄
- 보내기: codex queue --thread <UUID> --message '통신 시험 — MAIN 이 보냄 · 받으면 MAIN 에 «<내 이름> 수신» 을 queue 로 회신'(메시지는 늘 작은따옴표 — 큰따옴표면 bash 가 $decision-work 같은 $ 낱말을 빈 값으로 지운다)
	- 샌드박스에서 막히면 샌드박스 밖 실행 승인을 요청한다
- 보고는 표 한 줄씩: 이름 · UUID 앞 8자 · 큐 등록 성공/실패 · 회신(이 턴에는 «대기» — 회신이 오면 그때 채운다 · 기다리며 폴링하지 않는다)
