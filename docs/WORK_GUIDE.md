# 작업 가이드 — 이 기준으로 일한다

> 세션 시작 때 한 번 읽는다. 결과물 · 일하는 방식 · 이해(서술형 답을 제출물과 맞대 봄)를 본다. 하루 흐름 순서 12칸이고, 다른 문서는 칸 이름(굵은 글씨)으로 부른다.
> **C 번호**(Criteria · 기준) = 결정 문서(docs/ADR.md) 섹션마다 있는 «❇️ 성공 기준» 표의 줄 번호(C1 · C2 …). 섹션을 시작할 때 MAIN 이 직접 쓴다 · 무엇을 C 로 삼나 · 칸은 docs/DOC_GUIDE.md 3절 «성공 기준» · 모양은 docs/examples/ADR_example.md

## 시작할 때 — 무엇을 · 어디까지
| 칸 | 지킬 것 |
|---|---|
| **끝 조건** | «다 됐다» 를 판정할 상태를 먼저 쓴다 — 성공 기준(C 번호)은 나중에 대 볼 수 있는 문장 · 결과물 모양 · 제출 형식 · 한 번에 할 크기 |
| **맥락 · 경계** | 추측으로 빈칸을 채우지 않는다 — 필요한 파일 · 로그 · 지금 상태를 확인 · 하지 말 것 · 손댈 범위 · «왜 문제인지» · 요구에 없는 방어 · 기능은 넣지 않음(넣으면 근거 한 줄) |
| **쪼개 맡기기** | 확인 가능한 조각과 순서 · 조각마다 확인 지점 · **파일별 수정 범위**(빠지면 감점) · 범위 밖 변경은 하지 않고 제안만 |

## 작업 중 — 기록하고 확인하며
| 칸 | 지킬 것 |
|---|---|
| **기록 갱신** | 새 정보 · 실패가 생기면 문서를 바꾼다 — 결정과 이유 · 버린 안과 이유 · «AI 제안 → 유저 판단(채택 · 기각)» 을 갈라 적음 · 실패를 다음 단계에 반영 |
| **검증 고리** | 확인 → 고침 → 같은 확인 재통과로 닫는다 — 테스트 · 실행으로 확인 · «다 됐다» 는 따로 돌린 결과로만 · 사람이 승인할 곳을 정함 |
| **작업 체계** | 반복되는 일 · 넘겨줄 맥락은 문서 · 도구로 — 남이 이어받을 수 있게 · 만든 자산은 실제로 씀 · 자동화가 판단을 가리지 않게 · 규칙 · 도구를 늘리지 않음 |

## 결과물 — 코드 · 테스트 · 실행이 증거
| 칸 | 지킬 것 | 증거 |
|---|---|---|
| **돌아감** | 새 환경에서 처음부터 켜지고 실제로 동작 · 테스트 통과 · 가짜(mock)만이 아니라 실제 대상으로 한 바퀴 | run.sh · 실제 호출 기록(WORKLOG) |
| **구조** | 고치고 늘리기 쉬운 모양 — 외부 API 는 한 곳 · 에러는 종류별 · 동시에 써도 안 깨지는 저장 | src/api · 로그 종류 칸 · UNIQUE + 트랜잭션 테스트 |
| **비밀값** | 키 · 민감정보가 코드 · 로그 · 커밋에 없음 · 키는 환경변수로만 | $ready-end S1~S5 |

## 서술형 — 유저가 답을 제출물과 맞대 설명할 수 있게
| 칸 | 지킬 것 |
|---|---|
| **결정 이유** | 고른 구조 · 기술과 이유(요구 · 제약에 닿게) · 맞바꾼 것 · 포기한 것을 기록에 남긴다 |
| **구성 설명** | 파일 · 모듈 · 데이터 흐름 · 구현 / 개선 / 미구현 구분(못 한 것도) · 남이 확인할 근거 |
| **깨질 곳** | 정상 흐름 · 실패 · timeout 때 동작(꼭 묻는다) · 깨질 조건 · 다음에 볼 곳 |

서술형 답이 지킬 것 — 제출물과 어긋나지 않게 · 일반론 말고 이 결과물로 · 없는 걸 지어내지 않게 · 증거로
