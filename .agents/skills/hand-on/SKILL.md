# hand-on — 압축 직후 이어받기

압축 요약은 빠뜨리는 것이 있다. $hand-off 가 남긴 인계 칸과 문서, 그리고 압축 직전 대화 원문으로 맥락을 다시 채운다.

- 🔴 유저가 부를 때만 한다. 읽기만 한다 — 이 스킬 안에서는 파일을 고치거나 작업을 시작하지 않는다(4절의 유저 한 마디 뒤부터 작업)
- 확정한 값은 압축 요약이 아니라 문서에서 다시 확인한다

## 1. WORKLOG 인계 칸
- docs/WORKLOG.md 맨 위 «🔄 인계» 칸만 읽는다(INSP · 2ND 는 MAIN 의 인계라 참고만 — 내 일은 압축 요약 · 압축 전 채팅 요약에서 · 훅 글에 칸이 잘리지 않고 실려 있으면 다시 읽지 않는다 · 아래 기록은 필요할 때만)
- 칸이 비었거나 시각 · 커밋이 오래됐으면(마지막 커밋보다 앞) 그 사실을 4절 세 줄과 함께 알린다

## 2. 참조 중인 문서 — 적힌 부분만
- 인계 칸 아래 «참조 중인 문서» 목록의 경로 · 부분(절 · 섹션 · 블록)만 읽는다 — 문서를 통째로 다시 읽지 않는다

## 3. 압축 직전 10턴 — 이 세션 기록
- **훅이 걸려 있으면(scripts/hooks/install_hooks.sh)** 압축 직후 «[압축 직후 안내 — 훅이 넣은 글]» 이 맥락에 들어와 있다 → 거기 적힌 스냅숏 파일(~/.handoff/세션앞8자리_시각.md)을 읽는 것으로 이 절을 대신한다(압축 직전 10턴 · git 상태 · 인계 칸이 다 들어 있다)
- 훅 글이 없거나 «스냅숏 없음» 이면 아래대로 직접 뽑는다
- **내 기록 파일 찾기 — 명령 두 번, 같은 명령 안에서 부르지 않는다**(표식은 첫 명령이 끝난 뒤 기록에 적힌다)
	1. python3 ~/.codex/skills/ready-start/whoami.py mark → «WHOAMI-…» 한 줄
	2. python3 ~/.codex/skills/ready-start/whoami.py find WHOAMI-… → 결과 json 의 session_file
- **10턴 뽑기**: python3 ~/.codex/skills/hand-on/last_turns.py <session_file>
	- 유저 · 어시스턴트 메시지만 · 도구 호출 · 도구 출력 · 생각은 뺀다 · 길이 상한 없음
	- 압축 표시가 있으면 마지막 압축 표시 직전 10턴, 없으면 파일 끝 10턴(첫 줄에 어느 쪽인지 나온다)
	- 압축 표시가 없다고 나오면(새 세션 · 기록 형식 차이) 그대로 알리고 1 · 2절만으로 진행한다
- 인계 칸 · 문서와 10턴이 다르면(문서에 없는 결정 · 지시가 대화에만 있음) 4절에서 «문서에 없음» 으로 따로 짚는다 — 문서에 옮기는 것은 유저 한 마디 뒤
- **내 역할 스킬 다시 읽기**: ~/.codex/skills/<main · insp · 2nd>/SKILL.md 를 파일로 직접 읽는다(모델은 $스킬 을 못 부른다 · 세션 이름은 whoami.py · 이름이 없으면 압축 요약 · 시작 메시지($main · $insp · $2nd)로 정하고, 그것도 없으면 유저에게) — 공통 대회 맥락 · 역할 · 0-1 문서가 압축 요약에서 빠졌을 수 있다

## 4. 세 줄 보여 주고 기다린다
- 유저에게 세 줄만:
	- **지금 하던 일**: 섹션 · 단계 · 어디까지
	- **다음 할 일**: 바로 다음 한 동작
	- **열린 질문**: 번호만(ADR 🔴 · 승인 대기 · 지도 «확인할 것») — 대화에만 있던 것은 «문서에 없음» 표시
- 유저 한 마디(«진행» · 수정 지시)를 받은 뒤 작업을 시작한다 · 다른 세션이 queue 로 보낸 메시지는 유저 한 마디가 아니다(받았다고만 적고 계속 기다린다)
