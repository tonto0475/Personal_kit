# W1 — 책 이름 · 도메인 한 장 · 1장 «이 과제가 진짜 묻는 것» (19칸 · 4분)

**쓸 파일(이것만)**: `<책>/content/meta.py` · `<책>/content/s1.py` — 칸마다 주석에 «무엇을 넣나 · 분량» 과 예시 자리(«예: book_example/template_examples.md · 칸 이름» — 없으면 contracts/example/)가 있다
**읽을 것**: 과제 `README.md` · `<책>/contracts/reqs.json`(숨은 요구 · README 요구 · 말하지 않은 곳 — 1장 목록 칸에 **자동**으로 들어간다) · `facts.json` 의 `numbers` · `steps.json` 의 `figures.그림_큰흐름`
**1차판 먼저**(cards/README.md «두 번 내보내기» ③): A2 PASS 뒤 바로
**🔴 꼬리를 남기지 않는다**(리허설에서 `s1.py` 가 맨 끝이었다): 계약 전에 아래 칸의 **문장을 전부** 쓴다 — README · reqs.json 만으로 · 숫자 자리만 `{F['이름']}`(A2 가 알린 이름 · 모르면 짐작한 이름 — 1차판 · 중간판엔 회색 «2차판») → 보고하고 쉰다 → 지휘의 `followup_task` «<계약> PASS» 를 받으면 그 계약의 숫자 칸만 채운다(이름 맞추기 · 근거 숫자 · 문장을 다시 쓰지 않는다)

## 규칙(RULES 5절 s1)
- 첫 두 문단에 입력 범위 · 결과물 · 입력의 종류와 출처(파일 이름 · README)
- **진짜로 묻는 것** = 보통 3개 · 항목마다 **굵은 한 문장** + 실측 근거 2~3문장 · 처음 나오는 제약은 그 자리에서 출처(«N대 = 파일 N행») + «3장에서 확인할 질문»
- 출제 의도 추측에는 확신 수치(«확신 60%»)
- 분류 범례 다섯 모두(각 20자 안팎) — 파이프라인 = CSV 읽기 · 검사 · 정리 / 알고리즘 = 핵심 계산
- 맺음 = 3장에서 물을 것(뼈대를 바꾸는 것)의 이름 나열 — reqs.json `questions`(main) 와 맞춘다
- **도메인 한 장**(1장 맨 앞 상자 · 1차판에도 실린다) — 과제 분야를 처음 보는 독자(알고리즘 · 그 분야 지식 없음)가 이 상자만 읽고 README 를 따라올 수 있게. 네 칸 합쳐 반쪽(약 400~600자) · 분야가 뻔하면(일정 · 배송처럼) 칸마다 한 문장
  - 재료 = README 의 분야 낱말 · 파일 열 이름 · 단위 · 허용 값(그 밖 지식은 일반 상식만 — 회사 · 장비 고유 값을 지어내지 않는다) · 숫자는 `{F['이름']}`
  - **메커니즘 순서** — 재는 것(어디서 · 무엇을 · 몇 곳) → 단위(크기 감각) → 나쁜 것(어떻게 되면 불량 · 그러면 무슨 일 — 판정 기준 **굵게**) → 고치는 법(누가 무엇을 바꾸나 · 이 과제가 그중 어디를 돕나)
  - 비유 금지(그 분야의 실제 장비 · 공정 · 숫자로만) · 입문 밖 용어(오버레이 · 노광 · ppm 같은 것)는 처음 나오는 칸에 `("글", {"용어": "(영문) 설명"})` 각주 — 설명도 메커니즘으로
  - 예(측정 · 관리도 과제): 무엇을 재나 = 판 30곳에서 아래층 무늬와 위층 무늬의 위치 차이(dx · dy) · 단위 = nm(좌표 mm · 배율 ppm) · 나쁜 것 = **|평균| + 3σ 가 허용을 넘으면 재작업** · 고치는 법 = 성분별 보정값을 장비에 넣어 다음 묶음부터 되돌린다
- v3 서식: «무엇을» 1~2문장(v3 70자 · 결과물 한 구 **굵게**) · «입력_종류» 첫 구 · 결론 숫자 **굵게** · «출제_의도» 보려는 것 **굵게** — 빠지면 빌드 «서식: 굵게 없음» · 문단 350자 안(RULES 6절 칸 길이표) · 예: `book_example/task09/task09_kit.html` 1장 첫 쪽
