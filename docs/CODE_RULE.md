# CODE_RULE.md — 코딩 정책(코드 · git)

> 코드를 쓰거나 커밋하기 전에 읽는다. 기존 코드가 들어 있는 저장소를 고치는 과제면 이름 · 구조 · 주석 · 에러 처리는 그 저장소 방식이 먼저다($main 1-9 · $insp 1-9 · 유지보수와 인수인계가 쉬워서) — 이 문서는 새로 만드는 부분에 쓴다. 기존 스타일을 바꾸는 것도 수정 범위 승인 대상이다.

## 1. 단순하게 · 필요한 곳만
- 요청하지 않은 기능 · 유연성 · 설정 가능성을 더하지 않는다. 한 곳에서만 쓰는 코드에 추상화 금지. 일어날 수 없는 경우의 예외 처리 금지
- 요청 밖 기능은 구현하지 않고 결정 문서에 «⏸️ 제안 → 이유»로만
- 기존 코드를 고칠 때 옆 코드 · 주석 · 서식을 «개선»하지 않는다. 다르게 쓸 수 있어도 기존 스타일을 따른다. 내 변경으로 안 쓰게 된 것만 지운다
- 확인: 바뀐 줄마다 요청으로 거슬러 올라갈 수 있는가
- 예방: 범위 과잉 · diff 가 커져 무엇을 왜 바꿨는지 설명하지 못한다

## 2. 패키지 구성
- 루트: README.md(과제 지시문 · 수정 금지) · README_APP.md(우리가 만드는 앱 설명 — 키트에 들어 있음) · AGENTS.md · run.sh(실행 명령) · requirements.txt · .env(키는 유저가 채움) · .env.example(키 이름만) · .gitignore
- **docs/** — README · ADR · WORKLOG · CODE_RULE · UI_RULE · INTERVIEW · **surveys/**(설문 기록) · **examples/**(문서 예시)
- **src/** — api(외부 API 격리) · db(저장 · 조회) · core(계산 · 판정 · 순수 함수) · ui(화면) · observe(로그 · 설정 읽기 · health — lib/observe 에서 필요한 함수만 복사 · 앱 시작 때 한 번 켬)
- **config/** 설정 파일 · **tests/** test_*.py + conftest.py + fixtures/ + tmp/(버릴 임시 테스트) · **scripts/** 보조 스크립트(동시 요청 틀 race/ · 데이터 세기 ontology/ — 설문 · 점검 도구는 각 스킬 폴더 .agents/skills/ 안) · **assets/** 아이콘 · 차트용 한글 글꼴
- **data/** 입력 원본 · **out/** 결과물(제출물) · **logs/** app.log · debug.log
- 빈 폴더는 .gitkeep 으로 유지. 새 파일은 위 자리에만 만들고, 자리가 애매하면 결정 문서에 묻는다
- 예방: 파일이 루트에 흩어져 구조를 읽을 수 없다

## 3. 계층은 한 방향 · 외부 API 는 격리
- api · db → core → ui, 한 방향 의존만
- core: 데이터 → 결과 계산만. 외부 연동 객체 · 화면 프레임워크를 불러오지 않는다(테스트가 외부 없이 돈다)
- ui: 표시 · 입력만. 외부 연동을 직접 부르지 않는다
- observe: 어느 층이든 불러 쓴다(로그 · 설정) · observe 는 다른 층을 부르지 않는다
- 외부 API 호출은 **src/api 한 곳**으로 격리. 커져서 나눠도 격리는 유지
- 확인: core 파일에 화면 프레임워크 · 외부 연동 import 가 있으면 위반

## 4. 설정은 코드에 박지 않는다
- 주소 · 포트 · 임계값 · 경로 · timeout 은 config/ 설정 파일에 · 비밀값은 환경변수 · 매직넘버 금지

## 5. 외부 호출 timeout · 재시도
- 모든 외부 호출(API · DB)에 timeout. **기본 10초 · 오래 걸리는 호출(대용량 조회 · 업로드)만 30초**
- 값은 설정 파일에 · **담당자가 말한 값이 우선** · 합의한 값은 결정 문서에
- 재시도는 timeout · 연결 실패 · HTTP 429 · 502 · 503 · 504 에만(잠깐 몰림 · 게이트웨이 문제라 다시 보내면 될 수 있는 것), 횟수는 설정. 500 · 400대는 다시 보내도 같아 재시도하지 않는다. 넘으면 timeout 종류 에러로 기록(7절)
- 예방: 외부가 멈추면 프로그램 전체가 멈춘다

## 6. 중복 쓰기 방지 · 조용한 실패 금지
- 중복 · 동시 쓰기 방어는 **요구에 근거가 있을 때만** — 쓰기가 있고 같은 요청이 두 번 올 수 있다고 담당자 답 · README 가 말할 때(재시도 · 버튼 두 번 · 여러 사용자). 읽기뿐이면 넣지 않는다 · 넣지 않으면 이유 한 줄을 결정 문서에
- 예방: 요구에 없는 방어는 부하만 키우고 과설계로 감점된다
- 근거가 있으면: DB 에 쓸 때 «있는지 확인 + 쓰기»를 한 트랜잭션으로 · 중복 방지는 고유 제약(UNIQUE)으로 · 같은 요청 두 번에 한 번만 쌓이는지 테스트
- 그 테스트는 scripts/race/race_check.py 틀로: «요청 1번 보내기» · «행 수 세기» 두 함수만 바꿔 끼우면 동시 2번 · 0.1초 간격 2번을 보내 행 수 1 을 확인한다. sqlite 는 파일을 통째로 잠가 버그가 있어도 우연히 통과할 수 있어 «중복 금지 설정이 그 열에 걸렸나» 확인을 같이 단언한다
- 단계가 끝날 때마다 처리 건수 = 입력 건수 · 외부 응답 상태 · 형식 · 저장 건수를 확인하고, 어긋나면 에러로 처리하고 로그에 남긴다
- 예: 파싱 실패 행을 건너뛰고 «완료»(✗) / «입력 120 · 처리 118 · 실패 2(행 번호)»를 남기고 실패로 보고(✓)
- 예방: 구멍 난 데이터로 결과를 내고 아무도 모른다

## 7. 로그 — 두 파일 · 고정 형식
- **logs/app.log** — 항상(키트 src 양식엔 설정 코드가 없다 — lib/observe/obs_log.py 의 setup_logging 을 src/observe/ 로 복사해 앱 시작 때 한 번). 정보 수준 이상: 동작 상태 · 처리 결과(입력 · 처리 건수) · 에러
- **logs/debug.log** — 설정에서 켰을 때만. 디버그 수준 전부: 요청 · 응답 내용 · 중간 값(비밀값 · 개인정보는 가림)
- 칸 고정: 날짜 · 시간 · 기록 종류 · 중요도 · 관련 로직(처리 · 통신 · 화면 · 저장)
- 에러는 파일을 나누지 않고 **종류 칸**으로 나눈다: 입력 오류 · 외부 실패 · timeout · 내부 오류
- 코드에서도 이 네 종류를 **예외 클래스 4개**로 둔다 — src/core/errors.py(InputError · ExternalError · ExternalTimeout · InternalError, 공통 부모 AppError). 종류 값은 클래스의 kind 한 곳에서 정하고, 로그 종류 칸과 화면 메시지(screen_text)가 같은 값을 읽는다
- 과제에 없는 종류는 지운다(외부 호출이 없으면 ExternalError · ExternalTimeout 을 뺌) — 쓰지 않는 클래스는 과설계로 읽힌다
- 예: 결제 서비스가 10초 안에 답이 없으면 ExternalTimeout → 로그 종류 «timeout» → 화면 «[timeout] API 연결 실패 (timeout 10초)»
- 두 로그는 gitignore. 실제 구동 증거가 필요하면 마지막 app.log 를 out/ 으로 복사해 제출

## 8. 판정은 참거짓이 아니라 수치로
- 참/거짓만 돌려주지 말고 근거 수치(개수 · 편차 · 거리)를 같이 · 기준이 바뀌면 임계값만 고치면 되게

## 9. 주석 · 이름의 한글 뜻
- **모든 이름**이 처음 나오는 곳 **바로 위 줄**에 한글 뜻 주석: 모듈(파일 맨 위 한 줄) · 클래스 · 예외 클래스 · 함수 · 메서드 · 인자 · 클래스 속성 · 상수 · 전역 변수 · **지역 변수 · 반복 변수 · 예외 변수 · with 로 받는 이름까지**
- 인자가 여럿이면 한 줄에 «이름: 뜻 / 이름: 뜻»
- 문서에 코드 이름을 적을 때는 바로 뒤 괄호에 한글 뜻 — 예: fetch_orders(주문 목록 조회)
- 주석 문체: 한글 · 명사형 개조식 · AI 말투 금지(«~한다 · ~된다» 끝맺음 금지)

        # 외부 API 에서 주문 목록 조회. 실패하면 MAX_RETRY 번까지 다시 시도
        # url: 주문 API 주소
        def fetch_orders(url):
            # 시도 번호 — 1 부터
            for attempt in range(1, MAX_RETRY + 1):
                try:
                    # 응답 객체 — with 를 벗어나면 연결 닫힘
                    with urllib.request.urlopen(url, timeout=TIMEOUT_SEC) as resp:
                        # 응답 본문 문자열
                        body = resp.read().decode("utf-8")
                        return json.loads(body)
                # 연결 실패 · timeout 오류
                except OSError as err:
                    if attempt == MAX_RETRY:
                        raise err

- 예방: 유저가 영어 이름만으로 코드를 해석하지 못해 설명하지 못한다

## 10. 단위 · 인코딩
- 시간 · 크기 · 물리량은 단위를 이름에: timeout_sec(제한 시간 초) · size_mb(크기 메가바이트)
- 파일 읽기 · 쓰기 양쪽 모두 utf-8 명시 · 한글 출력은 출력 인코딩을 코드에서 정한다(컨테이너 로캘이 C · POSIX 일 수 있음) · 엑셀용 CSV 는 utf-8-sig
- 확인: 한글이 든 입력으로 한 번 돌려 결과 파일을 연다

## 11. git · 커밋
- 기본 브랜치에 직접 커밋(push 불가) · 실험은 브랜치로
- 단계 시작 전 커밋(.gitignore 먼저) · 검증 끝나면 다시 커밋 · 문서도 같은 커밋
- 메시지 = **[섹션] 무엇 - 왜**(실패를 고친 커밋은 «왜» 자리에 원인). 예: «[1-2] 주문 조회 모듈 - API 호출을 한 곳으로 격리, timeout 10초(담당자 합의)» · «[1-2] 재시도 누락 수정 - 검증 API-3 실패: 예외를 잡고 끝냄»
- 커밋을 합치지 않는다 — 실패 → 수정 → 재통과 흔적이 남아야 한다
- 버그 수정은 «재현 테스트 커밋(예상된 실패 표시를 붙여 전체 테스트는 통과) → 수정 커밋(표시를 뗌)» 순서 · 마지막 커밋은 반드시 통과($insp · $main 3-5)
- 커밋 전 git status --short 로 바뀐 파일을 전부 보고, 비밀 · 데이터 파일이 없는지 확인한 뒤 이번 작업 파일만 경로로 add(git add -A 금지) · 색인은 세 세션 공용이라 커밋도 git commit -m '…' -- 파일… 로 경로를 붙인다(남이 add 한 파일이 내 커밋에 섞이지 않게)
- 되돌리기는 git 으로 개별 파일만

### 11-1. 언제 커밋하나 — 사건 6개 · 관문 하나
- **관문** — 커밋 전 python3 -m pytest -q tests 종료코드 0 일 때만(폴더 지정 — 키트 전체를 돌리면 ref · lib 예제까지 수집돼 늘 실패 · 앱 기동 시험이 소켓을 써서 처음부터 샌드박스 밖 승인 · venv 를 만들었으면 python3 대신 .venv/bin/python). 버그 재현 테스트는 예상된 실패 표시(13절)를 붙여 관문을 통과시킨다
- **사건** — 아래 중 하나가 생기면 반드시 커밋한다

| # | 사건 | 메시지 예 |
|---|---|---|
| 1 | 결정 문서 섹션 하나가 합의됨(코드 전) | [1-2] 결정 — 재시도 3회 · timeout 10초(담당자 합의) |
| 2 | 성공 기준 C번호 하나의 테스트가 처음 통과 | [1-2] C3 중복 주문 차단 - UNIQUE + 트랜잭션 |
| 3 | 버그 재현 테스트를 씀(표시 붙임) | [1-2] C3 재현 - 동시 요청 2건이 둘 다 저장됨 |
| 4 | 그 버그 수정이 통과(표시 뗌) | [1-2] C3 수정 - 원인: 조회 후 삽입 사이 경쟁 → UNIQUE 위반을 잡아 기존 주문 반환 |
| 5 | 위험한 변경 직전(파일 3개 이상 · 구조 변경 · 의존성 추가 · DB 스키마 변경) | [1-3] 시작 전 기준점 |
| 6 | 단계가 끝나 WORKLOG 를 갱신함 | [1-2] 단계 끝 - 검증 통과 · 남은 것 2건 |

- **커밋하지 않는다** — 관문 실패 중 · 되돌릴 시도 중(버린 안은 WORKLOG 에 «A안 → 실패 이유 → B안» 한 줄)
- **크기** — 커밋 하나 = C번호 하나 또는 버그 하나. 30분 넘게 커밋이 없으면 C번호를 너무 크게 잡은 것 → 쪼갠다
- 이유: 디버그 이력이 «재현(무엇이 틀렸나) → 수정(원인 · 조치)» 두 커밋으로 log 에 남고, 헤맨 과정은 WORKLOG 에 증거로 남는다

## 12. gitignore
- 등록: .env · logs/app.log · logs/debug.log
- 미리 등록 후보는 .gitignore 안에 주석으로 둔다 — 필요해지면 줄 앞 # 를 지운다
- 패턴 뒤 같은 줄에 주석 금지(줄 전체가 패턴이 돼 무효)
- 결과물(out/) · 결정 문서 · 작업 기록 · 설문 기록은 **막지 않는다**. 넓은 패턴이 결과물까지 막는지 git check-ignore -v 로 확인

## 13. 테스트
- 검증 · 재현 · 회귀 확인용 코드는 tests/ 에 보관 · 이름은 검증 대상이 드러나게. 다시 검증할 일이 생기면 먼저 tests/ 를 본다(유효 → 바로 실행 / 안 맞음 → 그 부분만 고침 / 없음 → 새로 씀)
- 여러 테스트가 쓰는 준비물은 tests/conftest.py 에 픽스처로: 가짜 API 서버 · 테스트마다 새로 만드는 임시 DB · 원본 입력의 임시 복사본
- 원본(설정 · 원시 데이터)을 바꿔야 하는 테스트는 임시 복사본으로 · 실서버는 가짜로 · DB 는 커밋하지 않고 되돌린다(단위 테스트)
- **예상된 실패 표시** — 버그 재현 테스트에 붙여 커밋한다($insp · $main 3-5)

        @pytest.mark.xfail(raises=AssertionError, strict=True, reason="1-3 timeout 뒤 주문이 취소됨")

	- 버그가 남아 있으면 XFAIL(통과로 침) → 재현 커밋도 전체 테스트가 통과한다
	- 고쳐졌는데 표시가 남으면 XPASS(strict) 로 실패 → 표시를 떼고 수정 커밋
	- 준비 단계 오류(import · 이름 오타 · 픽스처)는 표시가 있어도 그대로 실패 — raises=AssertionError 가 가짜 RED 를 막는다(WSL pytest 7.4.4 실측)
	- TypeScript 는 ref/CHECKSHEET_TS.md(test.failing · test.fails)
