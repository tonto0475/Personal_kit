# flowtree — 작업 그래프 규칙 (MAIN · 2ND · 서브 공통)

> ⭐ 유저의 메인 작업소. 2차판 시점에 쉬운 것만 초안을 그리고 논의 뒤 보강하며($graph), 작업 · 검증 · 질문을 그래프 노드로 두고 유저가 devview 첫 화면(그래프)에서 본다. 이 문서 = 지금 동작(정본)

## 1. 역할 · 흐름
- 정본 범위 = 진행 상태 · 할 일(작업 · 검증 · 질문). 결정 · 이유는 docs/hand_off.md — 노드 본문은 짧게, 이유는 hand_off 항목 번호로 건다
- 흐름: 과제 파악(bookkit 책) → **2차판 시점에 쉬운 것만 초안(준비판 · $graph 1절 · 카드 bookkit/cards/P.md)** → 의사결정(유저와 대화 · hand_off 에 결정 · 이유 · 섹션 작업 순서) → 뼈대(skeleton) → **논의 뒤 보강(논의 반영 · $graph 2절)** → 구현 · 검증 · 질문
- 준비판 앞(과제 파악)에는 flowtree 를 쓰지 않는다 · 그리는 명세 = .agents/skills/graph/SKILL.md 3절
- 섹션 = 전체 구현 흐름 · 작업 순서(맨 위 작업 노드). 뼈대로 이미 만든 작업은 맞는 섹션에 **완료 노드**로 붙인다(`./kit graph skeleton` = skeleton/to_flowtree.py). 그 뒤 회색 테두리(미구현) 노드를 하나씩 구현 · 검증
- 구현 지시 · 검증 · 질문은 노드에서 마법봉으로 낸다: MAIN = hand_off 작업 · 검증 · 질문 노드(종류로 나눔 — 작업 → 구현 서브 · 검증 → 검증관 · 질문 → 놀고 있는 서브) · 2ND = 질문 노드(허브 magic.py 가 받음 · 단축키 Alt+Q = 허브 MAIN 마법봉 단추 · Alt+W = 허브 2ND 마법봉 단추)
- 벤치마크 그래프: 대회 전 리허설에서 유저가 만든 그래프를 여기에 둔다 — 지금은 없음

## 2. 화면
- 화면 = 그래프 위 화면 전환 스위치 `Main | 섹션0 | … | 섹션8`(총 10개 · flowtree_store.SCREENS) · 그래프 파일은 tree.json 하나 · 모듈 · 코드 화면 · 온톨로지 없음 · 그래프 제목 표시 없음 — 유저 지정 11/04
  - 노드 칸 `screen`(섹션 번호 · section 은 묶음 노드가 이미 씀). 칸이 없으면 부모 · 질문 대상의 섹션을 따름 · 그래도 없으면 Main 에만
  - Main = 모니터링: 섹션 칸과 무관하게 작업 · 파일 등 전부 보임 · 설문 · 검증은 안 보임 · 질문은 섹션을 못 찾은 것(Main 에서 만든 섬 질문 · Alt+R 대상 없음)만 Main 에 보임(답 · 상태 포함 · 섹션0 에는 안 겹침 · 유저 지정 11/05)
  - 섹션 화면 = 그 섹션의 모든 종류. 어느 섹션도 못 찾은 설문 · 검증은 섹션0 에 보임(Main 에 안 보이므로 어디에도 없게 되는 것을 막음) · 섹션이 있거나 대상이 섹션에 있는 질문은 그 섹션에만
  - 모든 화면이 자유 배치 — 끌어서 놓은 위치는 화면마다 따로(tree.user.json positions 의 feature = Main · s0 … = 섹션). 처음 나타나는 노드만 자동 배치 · 틀이 깔린 섹션 화면에서는 틀 오른쪽 밖에(틀과 안 겹침 · 끌어 둔 노드는 피함)
  - 고른 화면은 tree.user.json screen 칸(새로고침 뒤 유지). 화면을 바꿔도 선택 · 열린 자세히는 그대로 · 마법봉 · 삭제 · 함수 표는 어느 화면에서든 고른 노드로 동작 · 보이지 않는 노드에 걸린 선은 그 화면에서 안 그림
  - 패널에서 건너가기 · 알림 종(`postMessage {ft: 'focus', node}`)은 그 노드가 보이는 화면으로 옮겨 감
- 틀 — 모든 섹션 화면에 미리 깐 빈 노드(유저 지정 11/04 · 구현 때 노드를 만들지 않고 틀에 바로 채움)
  - 섹션마다 작업 4개(세로로 이음) · 작업마다 왼쪽 설문 2 · 오른쪽 검증 4 — 모두 그 작업에 직접 이어짐(병렬) = 28개 · 9섹션 252개 · 개수 = flowtree_store.FRAME_TASKS · FRAME_SURVEYS · FRAME_VERIFIES
  - id: `s<섹션>-t<k>` · `s<섹션>-t<k>-s<i>` · `s<섹션>-t<k>-v<j>`
  - 빈 틀 = 노드 칸 frame true(흐린 점선 테두리). Main · inbox · check · 알림에 안 나옴. 제목이나 내용(요약 · 설명 · 스크립트 · 함수 표 · 선택지 · 기록)이 들어오면 frame 칸이 떨어져 일반 노드
  - 깔기: 첫 쓰기 때 · 있는 그래프를 열 때 아직 안 깐 섹션에만 한 번(tree.json framed 목록) · 유저가 지운 노드는 다시 안 깖 · 처음 위치 = 노드 칸 pos0 · 끌어서 옮기면 앞 규칙대로 화면별 저장 · Main 은 자동 배치
  - 틀 작업을 지우면 아래 빈 틀도 같이 지움(채운 아래 노드가 있으면 거부)
- 노드 양식(오른쪽 패널 · 자세히에서 고침): 작업 = 기능 설명 · 설명 · 함수 표(파일 · 함수 · 설명 · ⭐) / 검증 = 검증할 내용 · 스크립트 경로 · 성공 · 실패 단추(유저 명령 `mark` — 결과 기록에 by user) / 설문 = 질문 칸(`edit`)
- 확대(펼침 줌)하면 노드 안에 상세 — 작업 = 함수 표(함수 · 설명 · 파일) · 검증 표(상태 · 내용 · 스크립트 · 안 채운 틀은 «빈 칸 N» 한 줄)
  - 설문 = 한 칸 흐름: 질문 → 배경 → 선택지 표(선택 · 내용 · 장점 · 단점 · 줄을 누르면 고름 · 추천 ⭐ + 노란 테두리 · 고른 줄 강조) → 기타(메모 칸이 열림 · 답 pick -1) · 보류 · 질문 → 추천 이유 → 유저 답. 투표 흐름은 그대로(inbox «설문 결정됨» → survey-ack)
  - 검증 = 한 칸 흐름: 제목 → 검증할 내용 → 스크립트 → 대상 → 성공 · 실패 단추 → 실행 기록 표(시각 · 결과 · 근거) · 질문 / 질문 = 질문 글 → 대상 → 답 → 상태
- 질문 단추 — 설문 · 작업 · 검증 노드(카드 · 상세 · 펼침 줌)와 패널(빈 틀 카드에는 없음). 누르면 그 노드에 이어진 질문 입력 노드가 옆에 붙음
- 그래프 파일(tree.json)이 없으면 빈 그래프로 시작 · 첫 노드를 저장할 때 폴더 · 파일이 생김 · 키트에 예시 그래프는 없음
- 노드 추가 단추(우하단 미니맵 위 4개): work(곡괭이) · insp(돋보기) · question(물음표) · suggest(설문)
  - 누름 = 고름(다시 누르거나 Esc 면 풀림) → 빈 곳 클릭 → 제목 입력 노드 → Enter 저장 · Esc 취소. 새 노드는 맨 위 · by user
  - 작업 · 검증 · 설문 = 유저 명령 `node-add` · 질문 = `ask` · 섹션 화면에서 만들면 그 섹션 소속 · Main 에서 만들면 칸 없음
  - 🔴 유저가 만든 설문 노드는 선택지가 비어 있다(경고만)
- 확대하면 자세히 — 줌 단계(점 → 카드 → 상세 → 펼침)가 노드 5종 공통
- 자세히(노드 우하단 ⓥ 또는 ` 키) = 오른쪽 절반 · 열린 채 다른 노드를 누르면 그 노드로 바뀜 · 노드의 «코드 화면 ›» 은 모듈 설명을 연다
- 작업 노드 함수 표(함수 · 설명 · 파일 · ⭐ · 함수 · 파일은 큰 파란 글자) — 자세히 · 오른쪽 패널에서 칸을 눌러 바로 고침(Enter 저장 · Esc 취소 · 벗어나면 저장) · ⭐ 누르면 핵심 토글 · «+ 행 추가» · 행 끝 × = 지우기 · 유저가 고친 칸은 연파랑 점선 밑줄 · 이름 바뀜 행은 주황 + «이름 바뀜 옛 → 새 — MAIN 반영 전» · 카드에 «ƒ 함수 이름들» · 펼침 줌에 표(읽기)

## 4. 그 밖 규칙
- 그래프 칸(노드의 graph) = `task` · `hand_off`(옛 `adr` 도 읽음) · 명령 `--graph task|hand_off`(`adr` 도 받음). 부모가 있으면 부모를 따름
- import-analysis — bookkit 분석 결과(reqs.json · facts.json)를 Task 노드로 불러온다(패키지 구조화에도 씀). 요구(분류 색) · 숨은 요구 · 파일 밑 함정 · 자료 사실 · 담당자 질문(선택지가 있으면 설문). 출처 열쇠 = 계약 항목 id(R1 · H3 · Q2 · T1 …) — 같은 id 는 다시 불러와도 갱신만(유저 답 보존) · id 가 빠진 항목이 있으면 불러오지 않고 실패(`check_contract.py <폴더> --add-ids` 로 채운다)
- 화면 칸(노드의 screen) = 섹션 번호 0~8 · 명령 `add` · `verify-add` · `survey-add` 의 `--section N` · 바꾸기 `section-set`(8절)
- 유저 명령 `node-add`(kind task · verify · survey · title · summary · section — 화면 단추 전용) · `node-del`(화면 Delete 키 · 아래 노드가 있으면 거부)
- 점검 코드: `graph-file-hand-off` · 유저가 만든 설문의 «선택지 없음» 은 오류가 아니라 경고

## 5. 파일 — 쓰는 쪽은 통로 하나
- 위치: docs/flowtree/ — tree.json(그래프 본체) · tree.auto.json(코드 스캔 · 자동) · tree.user.json(화면 배치 · 확인 기록 · 유저 화면만)
- 🔴 tree.json 을 직접 열어 고치지 않는다. 쓰기는 flowtree.py 명령(`./kit graph …`)으로만(잠금 tree.json.lock → 다시 읽기 → 고침 → 교체 · 동시에 써도 안 지워짐)
- 역할마다 쓸 수 있는 칸만 쓴다. 남의 칸은 명령이 거부한다(덮어쓰기 불가)

- 작업(task) — MAIN 이 만든다. 제목 · 요약(60자 이내) · 설명 · 연결 문서(doc)
  - 유저가 화면(패널 · 세부 보기)에서 제목 · 요약 · 설명을 고칠 수 있다 → edit 칸(유저 칸)에 따로 저장 · 보이는 값만 바뀌고 MAIN 이 쓴 원래 글은 남는다(show 에 «유저 고침 — 원래: …») · 비우면 원래 글로
  - 함수 표 칸 `funcs` = 행 목록 `{id: f1…, by, file, name, desc, core, user: {…}, code: {file, name}, del}`
    - file · name · desc · core = 에이전트 칸(원문 — add --func · funcs-set) · user = 유저가 고친 칸(행 · 칸 단위 — 화면) · 보이는 값 = 유저 칸 > 에이전트 칸. 에이전트 명령은 user 칸을 못 쓰고 유저 명령은 에이전트 칸을 못 쓴다
    - code = 코드에 있다고 확인된 (파일, 함수) — funcs-set 이 보낸 이름 · funcs-ack 가 쓴다. 보이는 (파일, 함수) 가 code 와 다르면(유저가 이름을 고침 · 유저가 새 행) «이름 바뀜» → MAIN inbox «tN [이름 바뀜] 제목 — 옛 → 새» · show 행 끝에도 표시
    - 이름 바뀜 처리: MAIN 이 서브에게 CODE_RULE 9-1 대로 파일 · 정의 · 부르는 곳 · import · 테스트 · 문서를 새 이름으로 → 시험 → `funcs-ack <작업>` 로 닫음. done 된 작업이면 «이름 바꾸기 — <작업>» 작업 노드도 그 밑에 자동으로(열린 것이 있으면 내용만 갱신)
    - del = 유저가 지운 에이전트 행(MAIN 이 같은 이름을 다시 보내도 되살리지 않음) · 유저가 만든 행은 지우면 빠짐
    - 옛 tree.json 의 names(«파일.py · 함수» 글자 목록)는 읽을 때 행으로 올리고(파일 글자 뒤 이름 = 그 파일의 함수) 처음 쓸 때 funcs 로 옮긴다
  - 고친 사람(user) · 시각 · 전 → 후 값이 «고친 기록»(edits)으로 남는다
- 설문(survey) — MAIN 만 만든다. 질문 · 선택지(라벨 · 풀이 · 장점 · 단점) · 추천(노란 테두리) · 추천 이유 · 배경
  - 화면: 카드 = 질문 + 선택지 칩 · 상세 줌 = 선택지마다 풀이 + 메모 칸 + «보류» · «질문» 단추 · 펼침 줌 = 배경 · 장단점 · 추천 이유 전문 · 세부 보기(ⓥ · `)에도 전문
  - 유저: 칩 클릭 = 선택(다시 누르면 해제) · 메모 · 보류 · «질문»(그 설문에 이어진 질문 노드) — 유저 답(votes)은 덧붙이기 기록
  - MAIN: inbox 에 «설문 결정됨(선택 · 메모)» · «설문 보류» 가 뜬다 → 반영한 뒤 `survey-ack <설문>` → inbox 에서 빠지고 노드에 «반영됨»
- 검증(verify) — MAIN 이 대상 노드에 붙여 만든다(무엇을 확인할지). 검증 서브(검증관)가 결과를 덧붙인다
- 질문(question) — 유저가 만든다. 대상 노드에 선으로 잇거나 섬으로 둔다. 2ND(MAIN 마법봉으로 보내면 MAIN 의 서브)가 답을 덧붙인다 · 허브 2ND 마법봉으로 보내면 devview 가 유저 이름으로 바로 등록(그래프 Ctrl+클릭 = 여럿 고르기)
- 파일(file) — 실제 파일을 띄우는 노드. 색 줄은 파일 형식별: CSV 청록(#2aacb8) · 과제 기본 제공 md 흰색 · PDF 빨강 · 그 밖(키트 안 md 포함 — 키트 md 는 흰색 금지) 회색
  - 키트 md 판정: 파일이 키트 폴더(작업 폴더부터 위로 git 루트까지 AGENTS.md 가 처음 있는 폴더) 안이면 키트 문서, 밖이면 과제 제공 · 경로 칸이 없는 파일 노드는 제목 확장자로
- 노드 안에는 요약만. 긴 내용은 세부 보기(노드에 마우스 → 우하단 ⓥ 단추 또는 ` 키 → 오른쪽 절반)
- 문서 연결: doc {path, anchor} — path 는 저장소 루트 기준 · anchor 는 hand_off.md 절 번호(«1-2») 또는 줄 끝 블록 id(«^이름») · 제목 글자로 찾지 않는다

## 7. 상태 · 테두리 색
- 빙글 = 진행 중 · 점멸 = 유저가 아직 확인 안 함(결과 상태로 바뀌면 점멸 → 유저가 노드를 누르면 고정)
- 줌아웃 점 표시에서도 같은 테두리 규칙(색 · 빙글 · 점멸)을 적용한다
- 진행 중 빙글 = 노랑(#f4d35e · 허브 행 · 대화 탭 · 칩의 작업 중 빙글과 같은 색) · 완료 = 녹색(#5fcf73 · 미확인이면 점멸) · 5분 넘음 = 주황(#ff9f43) 빙글 · 보류 노랑은 빙글 없이 점등

| 종류 | 흰색 | 노랑 빙글 | 주황 빙글 | 노랑 | 빨강 | 녹색 |
|---|---|---|---|---|---|---|
| 작업 | 미완 | 착수 | 착수 후 5분 넘게 완료 안 됨 | 보류 | 이상 · 유저 요청 필요 | 완료 |
| 검증 | 미검증 | 검증 중 | (없음) | 보류 | 비정상 | 정상 |
| 질문 | 미답변 | 답변 준비 중 | (없음) | (없음) | (없음) | 답변 완료 |
| 설문 | 미응답 | (없음) | (없음) | 보류 | (없음) | 선택됨 |

- 설문의 선택됨 · 보류는 유저가 직접 만든 결과라 점멸하지 않는다(점멸 = 에이전트 결과를 유저가 아직 안 봄)

- ⭐ 작업 «완료» = 그 작업의 파일 생성 · 코드 작성이 끝난 순간. 검증을 기다리지 않는다(검증은 검증 노드가 따로 표시) → 코드를 다 쓰면 바로 done

- 상태는 기록(답 · 검증 결과 · 작업 사건)에서 계산한다. 상태 칸을 따로 쓰지 않는다
- 검증 비정상이 MAIN 의 완료를 지우지 않는다 — 둘 다 보이고 판정은 유저
- 검증 결과 뒤에 대상 작업이 다시 done 되면 그 검증은 흰색(미검증 · 대상 다시 완료)으로 돌아가 --role insp inbox 에 다시 뜬다

## 8. 명령 — flowtree.py --role <역할> <명령>
- 부르는 법(작업 폴더 = docs/flowtree 가 있는 곳에서): `./kit graph --role main add - "제목" --summary "…"`(= `python3 devview/flowtree/flowtree.py …` · 옛 명령도 그대로 돈다 · 한글 · 따옴표가 섞이면 `--args '<JSON>'` — AGENTS.md 3절) · 다른 그래프는 `--tree <경로>`
  - 출력: 성공 한 줄(«t3 추가» · «q1 답변 완료») · 실패 «실패: 원인» 한 줄 + 종료코드 1 — 남의 역할 명령 · 60자 넘는 요약 · 결론 · 없는 id 는 거부
  - add 의 부모 «-» = 맨 위 · --graph 를 안 주면 부모 그래프(맨 위면 hand_off)
- MAIN: add <부모> "제목" --summary "…" [--graph task|hand_off] [--func "파일 | 함수 | 설명 | ⭐"]…(여러 번 · 옛 --names "파일.py · 함수" 도 받음) · start <작업> · hold <작업> "사유" · block <작업> "유저에게 필요한 것" · done <작업> · verify-add <대상> "확인할 것"
  - survey-add <대상|-> "질문" --option "라벨|풀이|장점;…|단점;…" (여러 번) [--recommend N(1부터)] [--why "추천 이유"] [--detail "배경 · 메커니즘"] [--graph task|hand_off] · survey-ack <설문> ["무엇을 했나"]
  - import-analysis <폴더>(reqs.json · facts.json → Task 노드 · 다시 하면 갱신)
  - file-add <파일|폴더>…(지급 파일 노드 → Main · 폴더면 안의 파일 전부 · 경로 기준 = 작업 폴더(--root) · 있는 경로는 그대로 · 뒤의 import-analysis 는 같은 이름이면 이 노드에 잇는다)
  - 틀 채우기: `fill <틀 노드> --title "…" [--summary …] [--text …] [--doc 경로#앵커] [--func "파일 | 함수 | 설명 | ⭐"]…`(작업) · `[--script 경로]`(검증) · `[--option …]… [--recommend N] [--why …] [--detail …]`(설문 · 제목 = 질문) — 준 칸만 · 유저 칸은 안 덮음 · `frames [섹션]`(공통 · 빈 틀 id)
  - 화면 섹션: add · verify-add · survey-add 에 `--section N`(0~8 · 없으면 칸 없음 — 화면에서 부모 · 대상을 따름) · `section-set <노드> <N|->`(있는 노드의 섹션 바꾸기 · «-» 면 칸 지움) · show 에 «섹션: N»
  - 함수 표: `funcs-set <작업> --row "파일 | 함수 | 설명 | ⭐"`(여러 번 · 4번째 칸 ⭐ · * · core = 핵심) 또는 `--json '[{"file":…,"name":…,"desc":…,"core":true}]'`(«@경로» 면 파일) — 보낸 목록 = 지금 코드의 함수 표. 같은 함수(보이는 이름 > 원문 이름 > 코드 이름) 행은 에이전트 칸 · code 갱신 · 목록에 없는 에이전트 행은 지움(유저 칸 있는 행 · 유저 행은 남김) · 유저 칸은 안 덮음
  - `funcs-ack <작업> ["무엇을 했나"]` — 유저가 바꾼 이름(· 새 행)을 코드 · 시험 · 문서에 반영함 → 이름 바뀜 닫힘(이름 바뀜이 없으면 거부) · show 에 «이름 반영» 기록
  - `funcs-scan <작업>` — 표의 .py 파일에서 함수 · 메서드 · 클래스 정의를 찾아 바로 위 주석 한 줄을 빈 설명 칸(에이전트 칸)에 · 코드에 없는 이름은 경고(파일 경로 = --root 기준 · 없으면 루트 아래 같은 이름 파일)
- 2ND(MAIN 의 서브가 질문에 답할 때도 이 역할 코드): answer-start <질문> · answer <질문> --short "결론 한 줄(60자)" "본문"
- 검증 서브(역할 코드 insp — 세션이 아니라 MAIN 의 검증관이 직접 쓴다): verify-start <검증> · verify-hold <검증> "사유" · run <검증> pass|fail "근거(시험 경로 · 명령)"
- 공통: inbox(내 역할이 할 일) · show <id>(노드 + 연결 노드 맥락) · check(형식 · 연결 · 앵커 점검)
- 유저(화면이 쓰는 명령 · 역할 user — 에이전트는 못 씀): vote <설문> [--pick N | --clear] [--memo …] [--hold | --unhold] · edit <작업 · 검증> [--title] [--summary] [--text] · funcs <작업> [--row f1] [--file …] [--name …] [--desc …] [--core | --no-core] [--del](행 id 없으면 새 행 · 화면 함수 표) · check-add <대상> "확인할 것" · node-add(노드 추가 단추 — 작업 · 검증 · 설문) · node-del(Delete 키)
  - 역할 칸 원칙: 유저 칸(edit · 함수 표 user 칸 · votes)은 에이전트 명령이 덮지 못하고, 에이전트 칸(제목 원문 · 사건 · 결과 · 답 · 반영 기록)은 유저 명령이 덮지 못한다
- 할 일은 inbox 로 직접 확인한다(세션끼리 메시지로 묻지 않는다)
  - 2ND: 미답변 질문 + 대상 노드 맥락 → 답변 준비 중으로 바꾸고 답한다
  - 검증관: 미검증 · 대상이 다시 완료된 검증(--role insp inbox) → 검증 중으로 바꾸고 결과를 남긴다
  - MAIN: 작업에 손대는 순간 start · 그 작업의 코드 작성이 끝나면 곧바로 done(시험 · 검증 전) · 유저 결정이 필요하면 block
  - MAIN: 유저 결정이 필요한 갈림길은 설문(survey-add)으로 띄운다 · inbox 의 «설문 결정됨» 은 반영 후 survey-ack · 작업에 함수 표가 있으면 그 이름으로 만든다 · inbox «이름 바뀜» = 그 이름으로 코드 · 시험 · 문서를 바꾸는 작업을 서브에게 → funcs-ack
