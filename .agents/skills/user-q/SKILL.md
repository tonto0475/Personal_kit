# user-q — 큐 모드 (2026-10-30 · 로컬 Claude 판과 같은 흐름 · 시작 신호에서 ❇️ · ;; 는 뺐다)

유저는 지시를 한 줄씩 여러 턴에 나눠 보낸다. 턴마다 생각하고 답하면 흐름이 끊기고, 큐에 무엇이 쌓였는지도 안 보인다. 그래서 받는 동안은 등록만 하고, 모아서 한 번에 정리 · 실행한다.

## 1. 받는 동안 — «등록했어.» 한 마디
- 유저 메시지마다 답은 정확히 «등록했어.» 한 마디. 요약 · 번호 · 의견 · 되묻기를 붙이지 않는다
- 도구를 쓰지 않는다(파일 읽기 · 검색 · 명령 · 서브 전부). 내용을 해석 · 판단하지 않는다 — 해석은 2절에서
- ❓ 질문 · 💭 같은 표식이 붙어도, 파일 경로 · 지시가 들어 있어도 등록만 한다
- 예외: 메시지에 3절 «시작» 신호 말이 있으면 큐를 닫는다 → 그 메시지 내용까지 등록하고 3절로 간다
- 등록은 대화 맥락에만 있다 — 압축되면 잃을 수 있다. 큐가 길어지면 유저가 정리를 부른다

## 2. «정리» 신호 — 할 일 표
- 신호: «정리 · 표로 · 목록 · 뭐 해야 돼» 처럼 큐를 펼쳐 달라는 말
- 이때부터 읽기 전용 확인(파일 · git · 문서)은 한다. 작업(수정 · 생성 · 커밋 · 설치)은 아직 하지 않는다
- 출력 순서
	1. **❓ 답변** — 큐 안의 질문에 답한다(질문은 답만 · 작업으로 읽지 않는다)
	2. **할 일 표** — 열: # · 할 일 · 출처(몇 번째 등록 · 문서 코멘트) · 고칠 곳 · 비고(겹침 · 의존 · 다른 세션과 충돌). 같은 대상을 고치는 등록은 한 줄로 합친다
	3. **하지 않는 것(보류)** — 유저가 보류한 것 · 답이 없어 판단이 필요한 것
	4. **순서 추천** — 선행 의존 · 다른 세션과 겹침으로 정하고 이유 한 줄
- 모호한 칸(범위 · 대상 · 할 일 종류가 둘로 읽힘)은 표 아래에 짚어 묻는다

## 3. «시작» 신호 — 큐를 닫고 실행
- 신호: «시작 · 진행 · 작업해»
- 유저가 번호 · 담당(«1 2 3 - 너 / 7 8 - 서브») · 순서를 정하면 그대로. 안 정했으면 2절 추천 순서
- 2절 표를 아직 안 냈으면 표부터 낸 뒤 같은 턴에 시작한다
- 서브로 넘기는 것은 먼저 띄워 두고(병렬) 직접 할 것을 진행한다
- 끝나면 표의 번호마다 결과(🟢 끝 · 🔴 막힘 · 보류)와 커밋 · 파일 경로를 한 번에 보고한다

## 4. 끝내기
- «큐 끝 · 일반 모드» 신호면 큐 모드를 끈다. 3절 실행이 끝나도 꺼진다
- 큐 모드 중에 «당장 · 지금» 이 붙은 메시지가 오면 그것만 바로 처리하고 큐 모드로 돌아간다
