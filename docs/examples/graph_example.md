# 그래프 예시 — 준비판 명령 순서 + 완성 그래프(9번 OHT 반송 모양 · 연습용 가짜 파일 이름)

`$graph` 준비판을 실제로 그린 예시다. 규칙은 `.agents/skills/graph/SKILL.md` 3절(명세) · 명령은 `docs/flowtree.md`.
아래 명령 블록은 시험이 그대로 돌린다(`.agents/skills/graph/test_example.py`) — 고치면 시험도 돌린다.

## 1. 세 칸 나누기(계획표 · 지도 «확인할 것» 을 보고)

| 계획표 항목 | 칸 | 이유 |
|---|---|---|
| K0 실행 · K3 화면 틀 | 바로 | 확인할 것에 안 걸리고 유저 결정도 없다 |
| K1 요청 읽기 · 검사 리포트 | 바로 | 보고만 한다 — 고칠지 버릴지는 안 정한다 |
| K2 저장 · 적용 | 설문 하나면 됨 | 같은 파일을 다시 올릴 때 덮어쓸지 새 판으로 쌓을지 = 유저 결정 |
| K4 기본 배차 계산 | 설문 하나면 됨 | 기본 규칙을 유저가 고르면 시작할 수 있다 |
| 결과 표 화면 | 설문 하나면 됨 | 표에서 무엇을 먼저 보일지 = 유저 결정 |
| K5 시험 틀 | 바로 | 과제와 무관한 틀 |
| 정비 중 OHT 를 배차에서 빼나(Q2) | 담당자 답 필요 | 그래프에 넣지 않고 질문 목록에만 |
| 하루 경계를 넘는 요청은 어느 날인가(Q5) | 담당자 답 필요 | 그래프에 넣지 않고 질문 목록에만 |

## 2. 명령 순서

```bash
# 빈 틀 확인 — 섹션0 = 준비판
FT frames 0
# 첫 조각 = 입력 → 처리 → 출력 순서로 틀 작업을 위에서부터 채운다
FT fill s0-t1 --title "앱 틀 · 실행" --summary "run.sh 로 뜨고 /health 가 답한다(K0 · K3)" --doc "docs/hand_off.md#1-1" --func "src/app.py | 앱_시작 | 설정을 읽고 서버를 띄운다 | ⭐"
FT fill s0-t2 --title "요청 파일 읽기 · 검사 리포트" --summary "CSV 를 읽어 문제 줄을 보고만 한다(K1)" --func "src/core/입력.py | 전부_읽기 | 과제 폴더 → 표 · 리포트 | ⭐" --func "src/core/입력.py | 요청_검사 | 줄마다 형식 문제를 모은다 |"
FT fill s0-t3 --title "저장 · 적용" --summary "검사를 통과한 표를 한 번에 저장한다(K2)" --func "src/core/저장.py | 적용 | DB 경로 · 표 → 판 번호 | ⭐"
FT fill s0-t4 --title "기본 배차 · 결과 표" --summary "정리된 표 → 요청마다 OHT 한 대 → 표로 본다(K4 · K3)" --func "src/core/계산.py | 배차_계산 | 정리된 표 → 배차 결과 | ⭐" --func "src/web/결과.py | 결과_화면 | 결과 표를 그린다 |"
# 틀에 안 들어가는 작업 = 다음 섹션 틀로
FT fill s1-t1 --title "시험 틀" --summary "같은 요청 두 번 · 경계값 · 냉시동 자리(K5)" --func "tests/conftest.py | 앱_띄우기 | 빈 DB 로 앱을 띄운다 |"
# 틀 밖 연결 — 세로 줄에 없는 가지 작업은 앞 작업을 부모로(회색 계층 선 · 설문 · 검증은 이 작업에 직접 붙인다)
FT add s1-t1 "시험 자료 만들기" --summary "경계값 요청 파일을 만든다(K5)" --section 1
# 검증 — 바로 칸 작업과 첫 조각의 끝에(그 작업의 틀 검증 칸)
FT fill s0-t2-v1 --title "문제 줄이 있는 파일을 넣으면 리포트에 그 줄 번호가 나온다" --script "tests/test_입력.py"
FT fill s0-t4-v1 --title "요청 파일을 올리면 결과 표까지 한 바퀴 돈다" --script "tests/test_한바퀴.py"
# 맨 앞 설문 — 답이 hand_off 1-1 수정 범위 승인이 된다
FT fill s0-t1-s1 --title "이 범위로 시작할까?" --option "이 범위로 시작|섹션0 작업 4개를 그대로 구현한다|바로 시작한다;첫 조각이 빨리 돈다|저장 방식은 다음 설문을 따른다" --option "범위를 줄인다|메모에 뺄 작업을 적는다|더 빨리 돈다|뺀 작업은 다음 섹션으로 밀린다" --option "범위를 고친다|메모에 더할 것을 적는다|빠진 요구를 넣는다|시작이 늦어진다" --recommend 1 --why "담당자 답 없이 만들 수 있는 것만 넣었고 한 바퀴가 가장 얇다" --detail "지금 범위는 앱 틀 · 요청 파일 읽기 · 저장 · 기본 배차 · 결과 표까지다. 정비 중인 OHT 를 배차에서 뺄지, 하루 경계를 넘는 요청을 어느 날로 볼지는 담당자 답을 기다리느라 빠져 있다. 이 범위로 시작하면 요청 파일을 올려 결과 표까지 도는 것을 먼저 볼 수 있다. 빠진 두 가지는 답이 오면 더한다."
# 설문 하나면 되는 작업 — 그 작업의 틀 설문 칸에
FT fill s0-t3-s1 --title "같은 파일을 다시 올리면?" --option "새 판으로 쌓는다|올릴 때마다 판 번호를 늘린다|이전 결과로 돌아갈 수 있다|저장이 늘어난다" --option "덮어쓴다|마지막 파일만 남긴다|코드가 짧다|이전 결과가 사라진다" --recommend 1 --why "과제가 이전 결과로 되돌리는 일을 막지 않아서, 남겨 두는 쪽이 안전하다" --detail "과제 글은 같은 요청 파일을 다시 올릴 때 어떻게 할지 말하지 않는다. 새 판으로 쌓으면 어제 결과와 오늘 결과를 나란히 볼 수 있다. 덮어쓰면 저장은 단순해지지만 어제 결과는 사라진다. 예를 들어 잘못된 파일을 올린 뒤 되돌리려면 새 판 쪽이어야 한다."
FT fill s0-t4-s1 --title "기본 배차 규칙은?" --option "생긴 순서로 가장 일찍 닿는 OHT|요청이 생긴 순서대로 가장 빨리 닿는 차에 맡긴다|규칙이 쉽다;바로 돈다|뒤 요청이 오래 기다릴 수 있다" --option "가까운 요청부터|OHT 마다 가장 가까운 요청을 고른다|빈 이동이 준다|먼 요청이 밀린다" --recommend 1 --why "첫 조각은 규칙이 쉬운 쪽이 빨리 돌고 결과도 눈으로 맞춰 볼 수 있다" --detail "요청마다 OHT 한 대를 어떤 순서로 맡길지 정한다. 생긴 순서로 맡기면 먼저 온 요청이 먼저 처리된다. 가까운 요청부터 맡기면 빈 이동은 줄지만 먼 요청은 오래 기다릴 수 있다. 예를 들어 멀리서 먼저 온 요청이 있을 때 두 규칙의 결과가 갈린다."
FT fill s0-t4-s2 --title "결과 표에서 먼저 보일 것은?" --option "요청별|요청 한 줄마다 맡은 OHT 와 시각|요구 문장과 같은 순서다|OHT 하루가 안 보인다" --option "OHT 별|OHT 한 대의 하루를 시간순으로|빈 시간이 보인다|요청을 찾기 어렵다" --recommend 1 --why "과제 글이 요청마다 결과를 확인하라고 하므로 그 순서가 맞다" --detail "결과 표의 첫 화면을 무엇으로 묶을지 정한다. 요청별이면 요청 하나의 처리 결과를 바로 찾는다. OHT 별이면 한 대가 하루에 어디서 놀았는지 보인다. 다른 쪽 보기는 뒤에 더할 수 있다."
# 점검
FT check
```

`FT` = `python3 devview/flowtree/flowtree.py --role main`(시험은 임시 `--tree` 를 붙인다).

## 3. 완성 그래프

```
섹션0 틀(세로로 이어짐 · 왼쪽 설문 칸 · 오른쪽 검증 칸)
s0-t1 앱 틀 · 실행 ◀ 설문 s0-t1-s1(이 범위로 시작할까?)
s0-t2 요청 파일 읽기 · 검사 리포트 ▶ 검증 s0-t2-v1(문제 줄 번호)
s0-t3 저장 · 적용 ◀ 설문 s0-t3-s1(같은 파일을 다시 올리면?)
s0-t4 기본 배차 · 결과 표 ◀ 설문 s0-t4-s1 · s0-t4-s2 ▶ 검증 s0-t4-v1(한 바퀴)
섹션1 틀
s1-t1 시험 틀 ─ t1 시험 자료 만들기(틀 밖 · 회색 계층 선 · 틀 오른쪽 밖에 놓임)
```

- 채운 작업 5개(섹션0 4 · 섹션1 1) · 틀 밖 작업 1개 · 설문 4개 · 검증 2개 · 담당자 질문 2개는 그래프 밖 · 나머지 틀 칸은 빈 채로 둔다(Main · inbox · check 에 안 걸린다)
- 설문 배경은 번호 없이 풀어 쓴다 — 유저가 그 노드만 읽고 고를 수 있게(규칙 = 명세 3절 «설문 문체»)
- 유저가 맨 앞 설문에서 «이 범위로 시작» 을 고르면 → inbox «설문 결정됨» → hand_off 1-1 수정 범위 승인 → `survey-ack` → s0-t1 부터 구현
- 함수 표 이름은 한글 임시 이름 — 구현 서브가 done 할 때 `funcs-set` 으로 실제 이름으로 바꾼다
