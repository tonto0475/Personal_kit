# survey — 세션 밖 화면에 묻고 보여 주기 (설문 폼 · 설명 폼)

유저는 터미널 글 대신 화면(devview 설문 탭)에서 읽고, 타이핑 대신 클릭 · 짧은 메모로 답한다. 기록은 docs/surveys/<프로젝트>/ 에 json 으로 남고 관련 문서 반영과 함께 커밋한다(작업 기록).

- **언제**: 유저에게 물을 것(결정 · 확인)이나 보여 줄 것(설명 · 비교 · 결과 · 유저가 궁금해한 것)이 **하나라도** 있으면 띄운다. 결정 문서(ADR)의 미논의 질문만이 아니다
	- 터미널 답이 길어지거나(표 · 비교 · 여러 항목) 유저가 나중에 다시 볼 내용이면 화면 쪽이 낫다
- **폼 고르기**: 유저가 골라야 하면 **설문 폼**(2 · 3절) · 읽고 메모만 하면 되면 **설명 폼**(2-1절) · 설명 없이 항목이 많아 대상만 고르면 **표 폼**(2-2절)

- 도구: 이 폴더의 survey.py · 시험 test_survey.py. 명령은 작업 폴더(키트)에서 실행한다(저장소 루트에서 치면 <루트>/docs/surveys 에 저장된다)
- 저장 폴더 = 지금 폴더가 속한 git 저장소의 docs/surveys · 프로젝트 = --project(없으면 저장소 이름) → docs/surveys/<프로젝트>/설문id.json
	- 다른 곳에 저장하려면 --dir 경로 를 **하위 명령 앞에** 붙인다(예: survey.py --dir docs/surveys new … · 뒤에 붙이면 «unrecognized arguments» 로 실패)
	- 🔴 저장 폴더 안의 json 중 questions 칸이 있는 것은 전부 설문으로 보인다 → 질문 파일은 /tmp 에 쓴다
	- 쓰던 답은 화면이 설문id.draft.json 에 자동 저장한다(다른 설문으로 갔다 와도 남음) · 제출 · 취소하면 지운다 — 커밋할 때 남아 있는 초안은 제출 안 한 설문의 것
- 이 폴더(.agents)는 Codex 에게 읽기 전용이다 — 도구는 실행만 하고, 결과는 docs/surveys 에 쓴다

## 1. 화면 — devview 의 «설문» 탭(기본) · 🔴 샌드박스 밖에서
- 화면 = devview 위쪽 **설문 탭**(Alt+8). 왼쪽에 프로젝트 → 대기 · 질문 · 완료(회색), 오른쪽에 답하는 폼(완료 설문은 당시 답을 읽기 전용으로)
	- 대기 · 완료 = 설문 폼(선택지)만 · **질문 = 설명 폼 전부**(답할 것이 위, 끝난 것은 회색)
	- 새 설문을 등록하면 열린 devview 의 설문 탭 **안에서** 2초 안에 그 설문이 열린다. devview 는 보던 화면 그대로 두고 알림 «새 설문 — Alt+S» · 배지만 띄운다(저절로 넘어가지 않음 · 열 때도 설문으로 바로 가지 않음)
	- → 등록한 뒤 유저에게 «설문 탭(Alt+S)에 올렸어» 한 줄로 알린다. 주소는 알려 줄 필요가 없다
- devview 가 떠 있는지 확인(처음부터 샌드박스 밖 승인 — 안에서는 떠 있어도 접속이 막힌다): curl -s http://127.0.0.1:8701/sv/api/state → seen_ago 가 든 json 이면 설문 연결된 devview(아래 생략)
- 안 떠 있으면 직접 띄우지 않고 유저 터미널 탭에서 칠 명령 한 줄을 준다(역할 스킬 공통 — Codex 가 띄운 서버는 끊긴 적 있음 · ReadyStart.txt 0번 줄과 같다)
	- bash <키트 폴더>/devview/dv (작업 폴더 = 키트 — AGENTS.md · docs 가 있는 곳, 없으면 지금 폴더 · 포트 8701) → 유저가 Browser 도구 PORT 8701
	- 이유: 리눅스 샌드박스(bwrap)는 네트워크를 따로 떼어 내고 로컬 연결도 기본으로 막는다 → 샌드박스 안에서 띄우면 Browser 도구가 서버에 못 닿을 수 있다. 등록(new) · 대기(wait)는 파일만 다루므로 샌드박스 안에서 해도 된다
- devview 를 못 쓰면 설문만 따로: python3 ~/.codex/skills/survey/survey.py serve --port 8600 (같은 화면 · 0.0.0.0) → Browser 도구 PORT 8600
- «Address already in use» → 이미 떠 있는 것(그대로 쓴다)
- 끝나면: /stop 으로 백그라운드 터미널 정지, 또는 서버 PID 로만 종료(kill PID · 이름 · 와일드카드 종료 금지)

## 2. 질문 파일 만들기 — 설문 폼
- 질문 파일을 /tmp/survey_주제.json 으로 쓴다. question · options 말고는 모두 선택 — 있는 칸만 화면에 나온다

        {"title": "MAIN · 결정 문서 · 1-1 · 1/2", "questions": [
          {"id": "1-2 #1", "question": "한 줄 질문",
           "decide": "유저가 결정할 것", "context": "배경 · 동작 원리", "example": "적용 예시",
           "pros": ["장점"], "cons": ["단점"], "recommend": "추천과 이유 · 확신 70%", "source": "원문",
           "options": [{"label": "(추천) A안", "detail": "고르면 무엇이 바뀌나", "pros": ["…"], "cons": ["…"], "example": "…"},
                       {"label": "B안", "detail": "…", "pros": ["…"], "cons": ["…"]}]}]}

- 화면(질문 카드 = 파랑): 맨 위 **결정할 것**(보라) → 배경 · 적용 예시(회색) → 제안(노랑 · recommend) → 선택지(글 길이만큼의 단추 · 추천은 노란 테두리 · 풀이 · 장단점 · 예시는 마우스를 올리면 바로 뜨는 툴팁) → 메모 칸(글만큼 늘어남) · 그 왼쪽 아래 **기타 · 보류 · 질문** 단추(누르면 선택지 선택이 풀림) → 원문(회색)
- **id**: 섹션 번호 · ADR 질문 줄의 #번호(예: 1-2 #1 — 답을 옮길 때 그 줄을 찾는 열쇠) / **question**: 한 줄
- **decide**: 유저가 무엇을 정하는지 1~2줄
- **context**: 무엇이 걸려 있나 · 동작 원리(2~6줄) / **example**: 고르면 실제로 무엇이 바뀌나(설정 줄 · 문서 모양)
- **pros · cons**: 질문 전체의 장단점. 선택지마다 다르면 선택지 안에 넣는다. 목록(["…", "…"])이면 한 줄씩 보인다
- **recommend**: 추천안 · 이유 · 확신 수치(«확신 70%»)
- **source**(선택): 근거 원문(결정 문서 · README 구간을 그대로 잘라서). 화면에 «원문» 상자로 보인다
- **images**(선택): 그림 경로 목록(png · jpg · svg 등) — 등록 때 설문 옆으로 복사돼 질문 바로 아래 그림으로 보인다(화면 후보 · 그래프를 고르게 할 때)
- **options**: 2~4개. 추천안을 맨 앞에, 라벨 머리에 «(추천)». 선택지마다 detail · pros · cons · example 을 줄 수 있다(툴팁으로 보임). **기타 · 보류 · 질문** 단추와 메모 칸은 도구가 자동으로 붙인다
- 글 칸은 짧은 마크다운을 받는다: **굵게** · `코드` · - 목록(탭 들여쓰기 = 한 단계 아래) · 1. 번호 · | 표 | · ``` 코드 블록
- **코드 이름(변수 · 함수 · 설정 키)을 쓰지 않는다** — 그 이름이 하는 일을 말로 쓴다. 유저가 화면에서 보는 이름(버튼 · 파일 이름)은 그대로
- 한 설문은 10문항 이내. 질문이 많으면 **작업 단위별로 나눠 여러 설문을 한꺼번에** 띄운다(답이 나오면 바로 할 수 있는 덩어리끼리)

## 2-1. 설명 폼 — 선택지 없이 설명 카드 + 항목마다 메모

- 질문 파일에 "mode": "explain" 을 넣거나, 아래처럼 items 로 쓰면 설명 폼이 된다(로컬 Claude 의 설명 폼과 같은 형식). 등록 · 대기 · 결과 명령은 설문과 같다(3절)

        {"title": "결과 보고 · 1차", "intro": "머리 설명(선택 · 짧은 마크다운)",
         "items": [{"id": "1", "title": "항목 제목", "body": "설명(짧은 마크다운 · 표 · 목록)",
                    "example": "예시(선택)", "source": "근거 원문(선택)"}]}

- 화면: 개요(회색) → 항목마다 제목 · 설명(회색) · 예시 · 원문 + 메모 칸 하나 → 추가 지시 → 제출 · 취소. 선택지 · 기타 · 보류 · 질문 단추는 없다
- 결과: answers[].kind = memo · memo = 유저 메모(빈 메모도 남음) · extra = 추가 지시. 메모가 질문이면 답하고(필요하면 새 설명 폼으로), 지시면 따른다
- 예시 파일: 이 폴더의 sample_explain.json

## 2-2. 표 폼 — 설명 없이 항목이 많을 때(행마다 X · △ · O + 메모)

- 질문 파일에 columns · rows 를 주면 표 폼이 된다. 행 = 칸 글 목록(id 는 순번) 또는 {"id", "cells"}. 칸 글은 **굵게** · `코드` 정도만. 등록 · 대기 · 결과 명령은 설문과 같다(3절)

        {"title": "ready-start 동작 — 대상 고르기", "intro": "머리 설명(선택)",
         "columns": ["절", "동작", "비고"], "rows": [["0", "라이브러리 확인", "막히면 venv"], {"id": "1-1", "cells": ["1-1", "문서 세트", ""]}]}

- 화면: 표 오른쪽에 X(미대상) · △(보류) · O(대상) 칸 · 행마다 바로 아래 메모 줄 → 추가 지시 → 제출 · 취소
- 결과: answers[].choice = X · △ · O(안 고르면 빈 값) · kind = skip · hold · target · none · label = 미대상 · 보류 · 대상 · 미선택 · memo · extra
- 시험: python3 ~/.codex/skills/survey/test_table_form.py

## 3. 등록 · 안내 · 결과 확인
- 등록: python3 ~/.codex/skills/survey/survey.py new /tmp/survey_주제.json [--project 이름] → 설문 id · 프로젝트가 json 으로 나온다
- 유저에게 한 줄로 안내 — 아래 1(devview 를 안 쓰면 «Browser 도구 PORT 8600»)

### 대기하지 않는다 — 등록하고 턴을 끝낸다 (토큰 · 2026-10-30 유저 지정)
- 🔴 wait 를 띄우거나 결과를 폴링하지 않는다 — 확인 한 번마다 모델 요청이 한 번 나가 맥락 전체가 다시 실린다(60초 한도로 5분 기다리면 요청 5번)
- **1.** 등록 → 안내 한 줄을 답변 **마지막 줄**에: «devview 설문 탭(Alt+S) · 질문 N개 · 제출하면 '제출' 한마디 보내 줘» → 턴을 끝낸다
	- 설문이 여러 개면 한꺼번에 등록하고 안내도 한 줄로(설문 id 를 다 적는다)
	- 설문 결과가 없어도 할 수 있는 일이 남았으면 그 일을 끝까지 하고 마지막 줄에 위 안내를 둔다
- **2.** 다음 턴 맨 처음(유저 말이 '제출' 이든 아니든) — 제출 안 본 설문마다 python3 ~/.codex/skills/survey/survey.py result 설문id
	- 결과 json → 먼저 유저에게 짧게 알린다(고른 답 · 메모 · 추가 지시 한두 줄) → 4절 반영
	- pending → «아직 제출 전 — 설문 id» 한 줄 · 유저의 새 지시는 평소대로 한다
	- 설문 id 를 잊었으면(압축 뒤): docs/surveys/<프로젝트>/ 에서 설문id.result.json 이 없는 설문id.json 이 제출 안 된 설문이다
- **3.** 유저가 브라우저 창을 닫는 것은 제출 · 취소가 아니다 — 그만두려면 화면의 «취소» 를 눌러야 action = cancel
- wait 명령은 도구 시험용으로만 남긴다(test_codex_flow.py) — 스킬 흐름에서는 부르지 않는다

### 시험 — 설문 흐름이 이 환경에서 되는지(대회 사전 체험 · 처음 쓸 때)
- 질문 파일 대신 이 폴더의 sample_questions.json 으로 등록한다: python3 ~/.codex/skills/survey/survey.py new ~/.codex/skills/survey/sample_questions.json
- 확인할 것: ① 서버가 샌드박스 밖에서 뜨고 Browser 도구로 열리는가 ② 등록 뒤 턴을 끝냄 → 제출 → '제출' 한마디 → result 로 결과를 받는가 ③ 결과 보고까지 걸린 시간
- 시험으로 생긴 docs/surveys/ 의 시험 설문 · 결과 파일은 커밋하지 않고 정확한 파일 경로로 지운다
- Codex 없이 흐름만 먼저 보려면: python3 ~/.codex/skills/survey/test_codex_flow.py — 임시 저장소에 devview 를 띄우고 등록 → wait → devview 화면으로 제출 → wait 종료까지 11개(10/29 WSL 11/11 · 제출 → 종료 0.19초).

## 4. 결과 반영
- **action = accept** — 문항마다 answers[].kind 로 가른다(choice · text · memo(메모) 가 같이 온다 · other · ask 칸은 옛 화면 호환용)
	- **option**(선택지) → 바로 결정 문서에 반영: 질문 아래 빈 칸에 «> > 🚹 답(text)», 그 아래 «🟢 결정 — 내용(🚹 설문 선택)». 블록 색 다시 판정
	- **other**(기타) → 메모 글을 유저 답으로 반영. 해석이 둘로 갈리면 다시 묻는 설문에 넣는다
	- **ask**(질문) → 메모의 질문에 대한 답을 조사 · 작성하고, 그 답을 배경(context)에 넣은 **새 설문**으로 다시 묻는다. 채팅에도 같은 답을 짧게
	- **hold**(보류) → 결정 문서는 그대로(미논의로 남김). 메모가 있으면 읽는다
	- 선택지에 붙은 메모(memo)가 지시(«~로 해 줘»)면 따르고, 질문이면 ask 처럼 답한 뒤 다시 묻는다
	- **extra**(맨 끝 추가 지시)가 있으면 유저가 직접 쓴 지시로 읽고 따른다
- **action = cancel** → 결정 문서는 그대로. 한 줄로 알리고 멈춘다
- 반영이 끝나면 docs/surveys/ 의 설문 · 결과 파일과 결정 문서를 **같은 커밋**으로: «[섹션] 설문 반영 · N문항 결정 · M문항 보류»
