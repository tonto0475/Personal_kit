# hand-off — 인계 남기기

압축은 앞 대화를 요약본으로 바꾸고, 새 세션은 앞 대화를 아예 모른다. 받는 쪽이 이 대화 없이도 이어 가게 «지금 어디까지 · 다음에 무엇 · 무엇을 보고 있었나 · 무엇을 버렸나 · 유저와 무엇을 하던 중이었나»를 WORKLOG 맨 위에 남긴다.

- 받는 쪽 = **압축 뒤 자신 · 새로 연 세션**. 옆에서 같이 도는 2ND · 서브에게 넘기는 양식이 아니다
- 섹션 끝 인계는 main 1-6(섹션 마무리) — 이 스킬은 유저가 부를 때만

- 🔴 유저가 부를 때만 한다. 맥락 % 를 보고 스스로 부르거나 «압축하자»고 권하지 않는다 — 압축 시점은 유저가 정한다
- 이 스킬은 /compact 를 실행하지 않는다(유저가 입력)
- 압축 훅(ready-start 3절)은 압축 직후 인계 칸 · 역할 스킬 절의 «경로» 만 넣는다 — 인계 칸 내용은 남기지 않으니 여전히 이 스킬로 쓴다

## 0. 첫 줄 — 덮어쓰기 확인
- 2ND 가 불렀으면 인계 칸을 쓰지 않는다 — 채팅에 세 줄(지금 하던 일 · 다음 · 열린 질문)만 남기고 끝(압축 요약에 남는다 · WORKLOG 는 MAIN 만 · AGENTS 2-6)
- 다른 일을 하기 전에 유저에게 한 줄로 묻는다: «WORKLOG 맨 위 인계 칸을 지금 상태로 덮어쓴다(지금 칸: «지금 하던 일» 첫 줄) — 진행?»
- 승인 뒤 시작한다. 압축 직후 이어받기($hand-on)를 부르려다 잘못 부른 것이면 여기서 멈춘다 — 아무것도 고치지 않는다

## 1. 누락 점검 — 새 세션이 이 대화 없이 이어 갈 수 있나
기준은 «이 대화를 전혀 모르는 새 세션» 이다(압축 뒤 자신보다 넓게). 범위는 상황에 맞춰 정하고, 적어도 아래를 본다:
- **내가 한 작업** — 이번에 한 커밋 · 바뀐 파일 · 실행 결과가 WORKLOG 기록 · hand_off.md(결정 · 섹션 작업 순서 · 진행 기록 · 검증 기록) · 데이터 지도에 빠짐없이 적혔나. 빠진 것은 그 문서에 먼저 적는다(기록 · 형식 칸은 `./kit worklog` · `./kit handoff` · 글은 파일에서 직접 · 빠진 곳 찾기 = `./kit status`)
- **최근 대화** — 최근 턴의 유저 · 어시스턴트 메시지를 훑어 문서에 안 옮긴 것: 유저가 정한 것 · 바뀐 지시 · 실측 값 · 약속한 다음 동작 · 아직 답 못 받은 질문. 대화 속에만 있던 것은 압축 · 새 세션에서 사라진다
- 내용은 정본 문서에 적고, 인계 칸에는 경로만 가리킨다

## 2. 인계 칸 고쳐 쓰기 — docs/WORKLOG.md 맨 위 «🔄 인계»
이 칸만 지금 상태로 바꾼다(아래 기록은 그대로):
- **지금 하던 일**: 섹션 번호 · 단계 · 어디까지(끝난 것 / 하다 만 것)
- **다음에 할 일**: 바로 다음 한 동작(파일 · 함수 이름까지)
- **열린 질문**: hand_off.md 🔴 · 수정 범위 승인 대기 · 지도 «확인할 것» 대기 · 회신 대기(검증관 검증 단계 · 커밋 / 설문 id / 2ND 에 준 글) — 번호만
- **마지막 통과 커밋**: 해시 · 무엇이 통과했나(명령 · 통과 수)
- **다음 세션이 먼저 읽을 스킬 파일**: 예 «~/.codex/skills/main/SKILL.md · 1-5 · docs/flowtree.md · docs/hand_off.md 해당 섹션»(모델은 $스킬 을 못 부른다)
- **버린 시도 · 이유**: 한 줄 — 같은 길을 다시 가지 않게(없으면 «없음»)
- **유저와 하던 일**: 유저와 논의 · 확인 중이던 것 — 유저가 마지막에 원한 것 · 내가 답한 것 · 유저 답 대기인 것(두세 줄)

## 3. 참조 중인 문서
- 지금 기대고 있는 문서마다 한 줄: 경로 · 어느 부분(절 · 섹션 · 블록) · 왜 보고 있었나
- 내용은 베끼지 않고 가리키기만(예: docs/hand_off.md 1-3 수정 범위 — 변경 1 승인 대기)
- 아직 문서에 안 적은 결정 · 실측 값이 있으면 먼저 그 문서(hand_off.md · 데이터 지도 · WORKLOG 기록)에 적는다 — 대화 속에만 있던 값은 압축되면 사라진다

## 4. 커밋 · 안내 — 커밋 한 번은 반드시
- 내가 바꾼 파일 중 커밋 안 된 것이 있으면(검증관의 tests/ · hand_off.md 검증 칸 등 서브가 쓰는 중인 변경은 빼고) 그 단계를 먼저 커밋하거나, 인계 칸에 «커밋 안 된 변경 있음 — 파일 목록»을 적는다
- WORKLOG(와 1절에서 고친 문서)를 정확한 경로로 커밋(`./kit commit docs/WORKLOG.md … -m`): «[인계] 섹션 · 단계». 이 커밋은 건너뛰지 않는다 — 다음 세션은 git 기록으로도 인계 시점을 찾는다
- 유저에게 한 줄: «인계 저장(커밋 해시) — 압축이면 /compact 뒤 $hand-on · 새 세션이면 역할 스킬($main · $2nd) 뒤 $hand-on»
