# ready-end — 제출 직전 최종 점검

도구가 걸린 곳을 **찾기만** 하고, Codex 가 걸린 줄을 읽어 진짜 문제인지 판단한 뒤 작은 커밋으로 고친다.

## 0. 이 대회에서 먼저 알 것 (사전 체험 · 제작진 영상 확인)
- **제출 = /home/user 폴더 전체**를 거둬 간다(git 커밋만이 아니다). 확정하면 더 못 고친다 · 확인 문제는 고정된 제출물로 만든다
- 채점 모델은 **실행까지 한다**(웹이면 화면을 열어 써 본다) → 새 환경에서 처음부터 켜지는지가 실행성 점수
- 과제 폴더 = 홈 = git 저장소(master · push 막힘). 플랫폼 파일(.bashrc · .profile · .literacy · .codex · .bash_history …)이 처음부터 미추적으로 있다
	- 🔴 **git add -A · git add . 금지** — .literacy/provider-env.sh(키)와 .bash_history 가 커밋된다
- **.env 는 없다** — 키는 플랫폼이 환경변수로 넣는다(OPENAI_API_KEY · OPENAI_BASE_URL 등) → 코드에 쓰거나 커밋하면 누출
- 🔴 **기록 파일은 지우지도 고치지도 않는다**(.bash_history · ~/.codex 세션 · .literacy) — 누출을 찾아도 보고만. 지우면 감독 · 기록 방해로 볼 수 있다
- 제출 직전에 결과물을 크게 바꾸면 의심받는다 → 고칠 것은 **작은 커밋 여러 개**로
- 출력도 수집된다 → **비밀값은 값을 찍지 않고 위치만**(도구가 그렇게 한다 · Codex 도 값을 다시 출력하지 않는다)

## 1. 시간표 (180분 과제 기준)
| 남은 시간 | 할 일 |
|---|---|
| 30분 | $ready-end → 맨 먼저 2ND 에 서술형 모의 준비 queue(5-1절) → 2절 점검 → 실패 항목 고치기(작은 커밋) |
| 25~20분 | MAIN 이 외우기 카드(5절)를 /tmp/ready_end_card.md 에 → 2ND 에 queue → 2ND 가 카드를 맨 앞 칸에 둔 서술형 모의 폼(5-1절)을 띄움 → 유저가 카드 읽고 문항 답 → 2ND 피드백 |
| 10분 | 유저 확인 항목(4절) → 제출 버튼 |

## 2. 점검 실행

        python3 ~/.codex/skills/ready-end/ready_end.py --card                 # 기본(테스트 포함)
        python3 ~/.codex/skills/ready-end/ready_end.py --start-port 3000      # run.sh 를 실제로 띄워 그 포트 응답까지

- 🔴 --start-port 와 R3 테스트(앱을 띄우는 시험 tests/test_ui_app.py)는 소켓을 쓴다 — Codex 샌드박스 안에서는 막혀 실패한다 → 점검은 처음부터 샌드박스 밖 승인으로 · venv 를 만들었으면 python3 대신 .venv/bin/python 으로 실행(R3 시험이 그 파이썬으로 돈다). **권한 상승(샌드박스 밖)** 으로 실행하거나 유저 터미널 탭에서 돌린다
- 출력: «✗ 번호 사유 파일:줄»(실패) · «△ 번호 사유»(확인 필요) · 마지막 줄 «요약: 실패 번호». 종료코드 1 = 실패 있음 · 2 = git 저장소 아님
- 키트(작업 폴더)에서 실행한다 — git 은 루트로, tests · requirements.txt · run.sh · docs 는 작업 폴더 기준으로 본다(첫 줄 «작업 폴더 kit» 확인 · 다르면 --work)
- 기본으로 빼는 경로(작업 폴더 안에서도): .agents/ · devview/ · ref/ · docs/examples/ · docs/surveys/ · scripts(envcheck · codex_config · hooks) · install.sh — 다 보려면 --all

## 3. 고치는 규칙
- 실패 하나 = 커밋 하나(CODE_RULE 11-1 · «[섹션] 무엇 - 왜») · 다 고친 뒤 ready_end.py 를 다시 돌려 «요약: 실패 없음» 확인
- 큰 정리 · 리팩터링 금지(막판 통째 변경은 의심 · 기능이 깨질 수 있음)
- 서버 종료는 내가 띄운 PID 로만(pkill · 이름 종료 금지)

## 4. 유저 확인 항목 (도구가 못 보는 것 — 유저에게 한 줄씩 부탁)
- 에디터에서 연 파일을 모두 저장(Ctrl+S) · «외부 변경 충돌» 띠가 없나(저장 안 한 내용은 제출에서 빠진다)
- Browser 도구로 앱 화면을 한 번 열어 핵심 동작이 되나(채점 모델이 똑같이 써 본다)
- 과제 README 의 «제출할 것»(파일 · 위치 · 결정 문서 칸)이 다 있나 — DECISIONS.md 처럼 과제가 이름을 정한 파일은 과제가 말한 위치(말이 없으면 <루트>)에

## 5. 서술형 외우기 카드 — MAIN 이 만들어 파일로 (--card 출력 재료로)
- 서술형 중에는 작업물을 못 본다 · 문항당 3~5분 · 붙여넣기 불가 → **최종 커밋 기준**으로 만들어 유저가 1~2분 읽고 들어간다
- 채팅에 출력하지 않고 **/tmp/ready_end_card.md** 에 쓴다(/home/user 밖이라 제출물에 안 섞임) — 서술형 모의 폼 맨 앞 칸이 된다(5-1절)
- 첫 줄 «최종 커밋 <해시> 기준» · 유형 6개를 굵은 제목(**① 핵심 동작 · 확인 방법** …)으로: 핵심 동작 · 구성(파일 · 모듈 · 데이터 흐름) · 확인 방법 / AI 제안을 확인 · 고친 곳 / 설계 결정과 버린 대안 / 예외 · 장애 때 동작 / 안 한 것과 이유 / 시간이 더 있으면
- 유형마다 **대표 1건 · 다른 사례** · 목록 1~2줄 — 숫자 · 커밋 해시 · 테스트 이름 · 담당자 말처럼 기록과 대조되는 사실로. 구현 / 개선 / 미구현 구분 · 지어내지 않는다(기록에 없는 건 쓰지 않는다)
- 모양: 같은 폴더 mock_form_example.json 의 0번 칸(가상 과제 예시)

## 5-1. 서술형 모의 — 2ND 가 카드 + 문항 설명 폼으로 한 번(MAIN 은 queue 만)
- MAIN: $ready-end 를 받으면 **맨 먼저** 2ND 에 queue 한 줄 — «서술형 모의 준비 — 문항 초안만» (UUID 는 whoami.py name 2ND) · 그다음 2절 점검
- MAIN: 점검 · 고치기가 끝나면 5절 카드를 쓰고 queue 한 줄 — «서술형 모의 띄워 — 최종 커밋 <해시> · 카드 /tmp/ready_end_card.md»
- 2ND: 설명 폼 하나로 띄운다(저장 폴더는 저장소 밖 — survey.py --dir /tmp/sv new … --project 2nd · 카드 전문이 제출 폴더에 남지 않게) — items[0] = «외우기 카드 — 최종 커밋 <해시> 기준»(body = 카드 파일 내용 그대로) · items[1~3] = 5절 유형에서 고른 문항(문항마다 3분 — 10분 안에 끝나게)(질문만 · 답 · 힌트 없음). 모양은 mock_form_example.json
- 유저: 카드를 1~2분 읽고 문항 메모 칸에 답을 직접 타이핑 → 제출 → 2ND 가 문항마다 피드백(2ND 스킬 «서술형 모의» 줄)
- 한 과제에 **한 번만**(리허설 포함)

## 6. 문서 점검(doc_check.py) — 따로 돌릴 때
저장소 루트에서:

- 끝 줄 «문제 없음 — 종료코드 0» 이면 통과 · «문제 N건 — 종료코드 1» 이면 아래대로 처리

- 시험: python3 -m pytest -q .agents/skills/ready-end

## 점검 4가지
1. **문서 경로** — docs/ 아래 문서(examples · surveys · CODE_RULE · UI_RULE 제외)에 적힌 src/ · tests/ · scripts/ · docs/ · config/ · data/ · out/ · assets/ · logs/ 경로가 실제로 있나. 괄호 · <> · «» · 별표가 든 자리 표시는 건너뛴다
2. **커밋 해시** — 표에서 머리 칸 이름에 «커밋» 이 든 열의 해시가 git 에 있나. «—» · 빈칸은 통과
3. **고아 문서** — docs/ 아래 .md 중 AGENTS.md · 다른 .md · 스킬 SKILL.md 어디에서도 경로나 파일 이름으로 가리키지 않는 것
4. **🚹 줄 보존** — docs/ 문서를 바꾼 커밋에서 내용이 있는 🚹 줄이 사라지거나 글자가 바뀌었나
	- 빈 답 칸(«> > 🚹») 채우기는 통과
	- 수정 범위 콜아웃 안 🚹 줄은 회차마다 다시 쓰는 칸이라 점검하지 않는다
	- AI 줄 속 출처 표시(«(🚹 동의)»)는 🚹 줄이 아니다 — 줄이 🚹 로 시작할 때만 유저 줄

## 결과 읽는 법 — 문제마다 할 일
- **경로** «파일:줄 — 경로» → 문서를 고치거나 파일을 만든다. «(생성 예정 목록)» 이 붙었으면 아직 안 만든 파일 — 만들 차례인지 계획이 바뀐 건지 본다
- **해시** «파일:줄 — 해시» → 표의 해시를 실제 커밋(git log --oneline)으로 고친다
- **고아** «docs/…md» → docs/DOC_GUIDE.md 1절 문서 지도에 «무엇 + 언제 읽나» 한 줄. 지울지는 유저 확인
- **🚹** «커밋 · 파일 · 사라진 줄» → 유저에게 확인. 유저가 직접 고친 거면 무시
- 문서를 고쳤으면 그 파일만 커밋하고 다시 돌려 «문제 없음» 을 확인한다
