# bookkit 품질 기준 — v3 «과제 파악 책» 과 같은 품질로 찍어 내기

> 기준(정본) = v3 책(`book_example/task10_guide_v3.html` · 펼침 PNG `book_example/Image/` · 원본 패키지 `book_example/task10v3_source/`) · 벤치마크 = 그것과 `book_example/task09/task09_kit.html` · 펼침 PNG `book_example/task09/Image/`.
> 양식(`template/`)은 v3 의 장 구성 · 블록 순서 · 상자 종류 · 그림 · 조작 블록을 그대로 떼어 낸 것이다 — 양식 + v3 내용 = v3 와 블록 169개가 바이트까지 같다(`books/_selftest_v3`).
> 이 문서는 **칸에 무엇을 어떻게 채우나**의 기준이다. 구조(«# ══ 구조» 아래)는 바꾸지 않는다 — 빌드가 «구조 바뀜» 으로 알린다.
> 내용이 들어가는 통로: 분석 → 계약 json(`contracts/` — 형식 `contracts/README.md`) → 장마다 칸 파일(`content/<장>.py`) → 장 파일 구조. 병렬로 나눠 쓸 때는 역할 카드(`cards/`)가 이 문서의 해당 부분을 옮겨 담았다.

## 1. 독자 · 목적

- **독자** = 해커톤 응시자. 개발 실무 지식이 적고 알고리즘을 배운 적이 없다. 풀어서 설명하면 이해한다. 대회는 AI 코딩 도구와 함께 180분
- **목적** = 읽고 나면 ① 문제를 정확히 파악하고 ② 시스템 · 알고리즘 방향을 정하고 ③ 담당자에게 물을 것을 알고 ④ 바로 착수한다
- 시각 자료가 이해에 가장 효과적이다 — 첫 쪽부터 그림 · 조작 블록(한눈에), 장마다 그림이 글보다 앞
- 목표 읽기 시간 10~15분(본문). v3 는 18~21분이었다(스티커가 요구한 확장 때문 — 한계로 기록). 늘릴 때는 «문제를 푸는 데 쓰이나» 만 묻는다

## 2. 교육 흐름 — 이 책에 필요한 것만(원본: 사용자 교육 정책)

| 규칙 | 이 책에서 |
|---|---|
| 쉬운 질문 → 막힘 → 이름 | 4장 첫 절: 가장 작은 경우는 전부 세면 된다(성공) → 크기가 늘면 곱으로 늘어 **실측 시간**으로 막힌다 → 그제서야 이름(«경로 문제») — 이름은 막힘 뒤에, 한 상자에 둘까지 |
| 메커니즘을 단계로 | 재생기 셋(채우기 · 한 곳씩 고치기 · 이어 붙이기) — 한 단계 = 한 동작, 단계 글 = 동작 + 결과 숫자 |
| 되돌아보기 · 규칙 한 줄 | 4장 «↩ 1장» 되돌아보기(1장 그림의 숫자를 그대로 다시 적는다) · 규칙 상자는 조건이 든 한 문장(«~이면 ~다») |
| 먼저 맞혀 보기 | 2장 · 4장에 하나씩, 답은 가린다(실측 숫자 + 이유) |
| **비유 금지** | 다른 분야 상황을 덧씌우지 않는다. 과제의 실제 상황(그 파일 · 그 숫자)으로만 설명한다 |
| **숫자는 실행값** | 글의 숫자는 전부 `content/data.py` 가 원본에서 계산한 값(f"… {F['이름']} …"). 손으로 적은 숫자 금지. 오래 걸리는 계산은 «저장 결과» 라고 밝힌다 |
| **각주** | 입문 밖 용어 · 약어는 처음 나오는 자리에 각주(«(영문 전체 이름) 설명»). 용어는 쪽 아래로 흩어 둔다(용어 사전 장 없음). 이미 단 용어는 다시 달지 않는다 · 빌드 경고 «각주 없이 처음 나온 코드 이름» 0 · 🔴 용어는 **그 블록 글에 글자 그대로** 있어야 한다(없으면 빌드 실패) · 재생기 용어는 재생기 칸의 `fn` 에(용어가 단계 글 · 캡션 안에 있어야) · 본문에 ¹ 를 손으로 넣지 않는다(이중 표식) |
| 압축 금지 | 지면에 맞추려고 단계를 빼지 않는다 — 쪽을 늘린다(부록은 특히) |
| 글 ↔ 그림 번갈아 · 한 단락 새 요소 하나 | 그림마다 바로 위나 아래에 «무엇을 보면 되는지» 한두 줄 |
| 쓰는 쪽 장치 숨김 | «단계 4 · F2» 같은 점검표 이름을 독자에게 보이지 않는다 |

## 3. v3 가 스스로 찾은 원칙 12개(REVISE_LOG) + 재생기 규칙 7

1. **요구 → 분류(색) → 만들 것** — 5분류 칩(화면 · 시스템 · 알고리즘 · 파이프라인 · 문서)을 1장 표 · 침묵 · 2장 함정 · 3장 질문 · 5장 주의 · 부록까지 같은 색으로
2. **그 자리에서 설명** — «이 책에서 N» · «N장 참고» 를 설명 대신 쓰지 않는다. 다른 장 언급은 설명을 다 한 뒤 «더 자세히» 로만
3. **처음 나오는 제약 · 숫자는 그 자리에서 출처** — «12대 = 차량 파일 12행» · «하루 3,274건 = 요청 파일 3일 평균» 처럼
4. **근거는 줄 번호가 아니라 실제 원본 줄** — 잘못된 예 · 정상 예를 나란히(`kit.raw` · `kit.mono`), 처리는 문장으로
5. **한 번에 하나** — 용어는 막힘마다 하나, 그림은 단계마다 바뀌는 것 하나
6. **그림은 메커니즘을 단계로 + 한 줄 말 설명**
7. **추론이 필요한 항목은 표 대신 ◎ 로 풀어 쓴다** — 질문(이유 · 추천 · 반대면) · 함정(실제 데이터 · 그냥 하면 · 이렇게) · 침묵(왜 문제인가 · 기본 가정) · 사실(실제 데이터 · 계획에 주는 영향 · 이렇게) · 5장 주의(왜 해당하나 · 이렇게)
8. **이해가 기대는 순서** — 무엇을 묻나 → 함정 → 질문 → 알고리즘 → 시스템
9. **문제를 푸는 데 쓰이지 않는 쪽은 뺀다** — 표지 · 차례 · 착수 순서 장 · 정본 숫자 표 · 방안 상세 · 한계 쪽
10. **잘 된 장치는 유지 · 확장** — 흩어진 각주 · 굵은 강조 · 채우기 재생기 · 시스템 층 그림 · 생각해 보기 · 함정 장
11. **시각 자료 먼저** — 첫 쪽부터 그림과 조작 블록(한눈에), 장마다 그림이 글보다 앞
12. **부록은 쪽이 늘어도 풀어 쓴다** — 짧은 표 칸 대신 문장 두 개

재생기(시각화) 규칙 — 채우기 재생기가 통하고 «결과 스냅샷» 재생기가 안 통한 차이에서 뽑았다
1. 한 단계 = 한 동작(담기 하나 · 고치기 한 번 · 일 하나 붙이기) — 단계 사이에 바뀌는 것이 하나뿐
2. 같은 그림 · 같은 표 위에서 — 지금 단계 행 강조 · 앞으로 올 행은 흐리게 · 바뀐 것만 굵게 · 빨간 ×
3. 색 = 정체성 — 차 하나 = 색 하나, 끝까지 같은 색(`figs.COLORS`)
4. «해 보기» 한 줄 — 무엇을 보며 누를지(«07~10시에 일하는 차가 보유 12대에 닿는 순간»)
5. 단계 글 = 동작 + 결과 숫자 — «급함 요청을 OHT 1 에 맡긴다 — 이 차 오늘 27건째»
6. 끝 상태가 허점이나 결론을 드러낸다 — 지그재그 · 빨간 칸 · 보유선 위로 올라간 차
7. 결과 스냅샷이 아니라 메커니즘 — 조건별 결과를 넘기기만 하는 재생기는 «왜» 를 못 보인다

## 6. 크기 기준 — 브라우저 검사가 없을 때 미리 지킨다

쪽 = 폭 **664px · 내용 높이 약 990px**. 블록은 **쪼개지지 않는다** — 한 블록이 990px 를 넘으면 «쪽보다 큰 블록» 실패, 폭이 664px 를 넘으면 «쪽 가로 넘침» 실패. `with w.keep()` 묶음(작은 제목 + 문단 + 재생기)은 한 쪽에 들어가야 한다.

서식 규칙(빌드 «서식:» 이 잡는다)
- 절 제목에 번호를 붙이지 않는다(«4.1 …» ✗ · «OHT 한 대의 순서부터 — 전부 세면 되나») — 카드 · 칸 주석의 «4.1» 은 구획 이름일 뿐
- **굵게** 를 v3 처럼 — 1장 «무엇을»(결과물 한 구) · «입력_종류»(첫 구 · 결론 숫자) · «출제_의도»(보려는 것) · 2장 «가장_큰_함정»(결론) · 부록 A 첫 문장, 진짜로 묻는 것은 항목마다 **굵은 한 문장**
- 계약 설명 글(원본 줄 사이 색 `null`)의 `{F['이름']}` 은 빌드가 채운다 — 원본 조각(색 `""` · bad · good) · 결함 칩 글자 안에는 식을 쓰지 않는다(계산되지 않아 «{F[…]}» 가 책에 그대로 — 빌드 «식 글자 남음» = `--strict` 실패)
- 2차판에 «⟪…⟫»(1차판 표시)가 남지 않게 — steps.json `"data": "raw"` 는 A1 뒤 정리한 자료로 다시 돌려 `"clean"`
- 판은 덮어쓰지 않는다 — 새 판 = 새 파일 `dist/<doc>__v<N>_<판 이름>.html`(빌드가 자동 · 유저가 읽던 앞 판이 남는다) · 담당자 답 · 유저 결정 변경으로 방향을 바꾼 판은 `--label "<짧은 이름>"` · 내용(content)을 고치기 전 앞 판 html 은 그대로 둔다
