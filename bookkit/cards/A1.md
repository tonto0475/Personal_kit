# A1 — 자료 함정 → contracts/facts.json (5분)

**읽을 것**: A0 산출물(`<책>/work/inventory.md` · 있으면 그 숫자로 시작) · 과제 `README.md`(제공 자료 절) · `uploads/` 전부(읽기만) · `bookkit/contracts/README.md` 의 «facts.json» 절 · 예 `bookkit/contracts/example/facts.json`
**쓸 것**: `<책>/work/a1.py`(계산 스크립트) → `<책>/contracts/facts.json` · 다른 파일은 고치지 않는다(이어서 지도 칸은 맨 아래 절 — 지휘가 «이어서 지도» 를 보낼 때만)
**언제**: A0 가 끝나면 A2 · A3 과 같이 시작한다(1차판을 기다리지 않는다)

## 둘로 나눠 맡기 — 파일 4개 이상이면(3개 이하면 나누지 않고 한 서브가 아래 «할 일» 전부)
- **나누는 사람** = 지휘 — A0 의 `work/files_scan.json` 파일 목록으로 앞 묶음 · 뒤 묶음을 정해 첫 지시에 파일 이름을 적어 준다 · 크기 합이 비슷하게 · 같은 키로 이어지는 파일은 되도록 같은 묶음에
- **뒤 묶음(A1b)**: 자기 파일만 «할 일» 1 ~ 3 → `work/a1b.py` → `work/facts_b.json`(조각) — 칸은 facts.json 과 같다(`numbers` · `files` · `traps` · `defects` · `facts` · `report` · 가장 큰 함정이 자기 묶음이면 `figures.그림_자료띠`) · 함정 후보는 개수를 맞추지 말고 다 넣는다 · `id` 는 붙이지 않는다 · `numbers` 이름 앞에 `b_` · 임시 파일에 쓴 뒤 `os.replace` 로 한 번에 옮긴다(반쯤 쓴 조각을 읽지 않게) · `contracts/` · 지도는 건드리지 않는다
  - 끝 신호: «A1b 조각 — 함정 N · 결함 N · 사실 N · 숫자 N» 한 줄 → 지휘가 이 서브를 닫는다
- **앞 묶음(A1a) = 합치는 쪽**: 자기 파일을 `work/a1.py` 로 → 끝나면 `work/facts_b.json` 이 있나 본다 — 있으면 바로 합치고 · 없으면 «A1a 끝 · 조각 대기» 한 줄 보고 후 쉰다(지휘가 조각을 받으면 `followup_task` «A1 합치기»)
- **합치기**(`a1.py` 끝에 코드로 — 손으로 베끼지 않는다): `numbers` · `files` 합치기 · 묶음 사이 키 검사(다른 파일과 안 이어지는 키 — 두 묶음 파일을 함께 읽는다) · 두 묶음 함정 후보 중 큰 것 5 ~ 8 만 `traps`(나머지는 `defects` 로) · 개수 · 순서를 아래 규칙대로 · `figures.C_적용_그림` 은 파일 전체로 · id 는 합칠 때 붙인다 → `contracts/facts.json` 하나 → 아래 «끝 신호»
- 이어서 지도 = **합친 쪽**(뒤 묶음 파일의 숫자는 `work/a1b.py` · `work/facts_b.json` 에서 읽는다 — 다시 조사하지 않는다)

## 할 일
1. `work/a1.py` 에서 파일마다 읽는다(모든 칸을 글자 그대로 — pandas 면 `dtype=str, keep_default_na=False, encoding="utf-8-sig"`) → 행 수 · 기간
2. 파일마다 검사를 하나씩(큰 틀 먼저): 형식 다른 구간 · 키 모양(앞자리 0 · 공백 · 대소문자) · 중복 · 빈 칸 · 범위 밖 값 · 코드 표기 변형 · 다른 파일과 안 이어지는 키 · BOM
3. 함정마다 «정리한 값 vs 그냥 읽은 값» 을 **실제로 계산**한다 — 에러 없이 틀린 숫자가 나오는 것이 큰 함정(`big: true`)
4. json 을 쓴다(스크립트가 `json.dump(..., ensure_ascii=False, indent=1)`):
   - `numbers` — 글에 쓸 실측 값 전부(이름은 영문 짧게 · 집필 · A2 가 `F['이름']` 로 쓴다)
   - `files` — `{"name", "desc"(짧은 설명 — 부록 A 작은 제목이 «파일 — desc»), "rows"}`
   - `traps` 5~8(big) + 나머지는 `defects` 로 — `raw` 는 원본 줄을 **파일에서 읽어** 넣는다(손으로 베끼지 않는다) · 잘못된 예 `"bad"` · 정상 예 `"good"` 를 나란히 · `naive` = 실측 틀린 숫자 `!!빨강!!` · `fix` = 고치는 법 + 리포트에 남길 것
   - `defects` — 파일 순서대로(같은 파일끼리 붙여서) · `what` = `**무엇**(개수)` · `bad` 원본 칸 그대로 · `fix` 두 문장
   - `facts` 8~12 — 고칠 수 없지만 계획에 영향을 주는 것(`effect` 숫자로)
   - `report` 6~8 — 이 자료의 실제 줄(파일 · 줄 번호 · 종류 · 원본 값 · 처리)
   - `figures.그림_자료띠` — 가장 큰 함정의 줄 구간(구간 2~6 · 줄 번호는 원본에서 센 값) + 정리 전후 막대(`figs.file_band` 칸 — 설명 글 45자 이하 · 왼쪽 가장자리 구간은 `"anchor": "start"` · `above` 글은 띠 오른쪽 절반에만)
   - `figures.C_적용_그림` — `bookkit/analysis/_common.py` 의 `txn_fig({파일: 행 수}, 실패 위치)`(sqlite 메모리 DB 로 실제로 넣어 본다 · 상자 이름 영문 11자 · 한글 6자 안쪽)

   - **id** — traps `T1…` · defects `D1…` · facts `F1…` · report `P1…`(책의 번호 · 블록 ID 가 이 id — 다시 돌려도 같은 항목은 같은 id)

## 규칙(RULES 에서)
- 함정은 데이터 종류가 아니라 **파일별** · 근거는 줄 번호가 아니라 **실제 원본 줄**
- 함정은 계획을 크게 바꾸는 것만 5~8(나머지는 defects) · 결함 표 하나 6행(넘으면 자동으로 나뉜다)
- 비유 금지 · 숫자는 계산값만

## v3 서식(RULES 6절 «칸 길이표» — 검사기가 «v3 한도» 경고로 알린다 · 경고 0 으로 맞춘다)
- 2장 ◎ 카드 = 제목 `what` 48자 · `naive` 150 · `fix` 100 · 카드 전체 360자 안 — 칸마다 2~3문장, 원본 조각은 두세 개(벤치마크 책 2장의 함정 카드 길이 · 모양 참고)
- `raw` 의 설명 글(색 `null`)에는 `{F['이름']}` 을 써도 된다(빌드가 채운다) · 원본 조각(색 `""` · bad · good)에는 식 금지(FAIL)
- 결함 `bad` · `good` = 원본에 글자 그대로 있는 값만 칩 — 여러 값은 « · » 로 잇는다(칩이 하나씩) · **원본에 없는 설명**(«키마다 한 줄» · «A 또는 B» · «값 범위 0~100»)은 `[["키마다 한 줄", null]]` — v3 는 칩 없는 글이다(`--task` 가 «원본에 없다» 로 잡는다)
- 결함 순서 = 가장 큰 함정의 파일부터(함정이 가장 큰 파일 → 그다음 파일) · `what` 55자 · `fix` 115자
- 사실 ◎ `title` 32자 · `effect` 120자 · `do` 75자
