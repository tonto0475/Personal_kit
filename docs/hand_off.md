# hand_off — (과제 이름) 결정 · 작업 순서 · 인수인계 문서

> [!abstract] 한 줄 요약
> (무엇을 만드는 과제인지 한 줄). 이 문서는 **결정 기록(무엇을 · 왜)** 과 **섹션별로 어떤 순서로 작업했는지** 를 남긴다 — 섹션마다 설계 상세 · 수정 범위 승인 · 검증 기록 · 결정 이유, 진행 기록 아래 «섹션 작업 순서» 표에 작업 흐름. 채점 모델이 읽는 문서이면서, 이 문서만 읽고 후임자가 일을 이어받을 수 있는 인수인계 문서다. 진행 상태(노드 · 완료 여부)의 정본은 flowtree(docs/flowtree.md — 2차판 시점 초안 → 논의 뒤 보강)다. 유저 · 구현자 · 검증자는 섹션 번호(1-1 …)로 소통한다.

> [!example] 작업 개요 — 유저와 대화로 쌓는 곳(어려운 말 없이 · 2단계)
> - **무엇을 만들고 붙이나**: (큰 흐름 — 만들 것 판정은 지도)
> - **핵심 흐름**: (데이터가 어디서 와서 어디로 가나)
> - **전체 결정(섹션 밖)**: (스택 · 구조 · 범위 — 결정 · 이유)
> - **뼈대 파일 · 함수 표**(K1 · K2 · K4 — 유저 확인 뒤 서브가 구현): | 파일 | 함수 · 이름(한글) | 하는 일 | 확인 |
> - **섹션 목록**: 1-1 (입력 → 처리 → 출력 한 바퀴) → 1-2 … — 아래 진행 기록 표와 같은 순서

> [!tip] 읽는 법
> - 섹션 = 기능 · 작업 하나(저위험 = 화면 · 배치 · 스타일 / 민감 = 처리 흐름 · 외부 API · DB 쓰기) · 블록 8개: 수정 범위 · 목표 · 성공 기준(C1 · C2 …) · 배경 · 논의 내용(회차마다) · 결과 정리 · 검증 기록 · 코드 개선 제안
> - 기호: 🔴 논의 필요 · 🟢 완료 · 🟠 승인 대기 · ⏸️ 보류 · ⬜ 대기 · 🔄 진행 · ➖ 해당 없음 · 🚹 유저가 쓴 줄 · 🤖 AI 가 쓴 줄
> - 상자 색: 빨강 = 그 블록에 논의 필요 · 미검증이 남음 · 초록 = 다 끝남 · 주황 = 수정 범위 승인 대기
> - 쓰는 법: docs/DOC_GUIDE.md 3절 · 채운 예시: docs/examples/hand_off_example.md
