# UI_RULE.md — 프론트 정책

> 화면을 만들거나 고치기 전에 읽는다.

## 0. 실행 규칙
- 서버는 0.0.0.0 에 바인딩한다 — 127.0.0.1 이면 IDE 의 Browser 도구에서 안 보인다
- 포트는 3000(과제가 정하면 그 값) · 환경변수 PORT 로 바꾼다
- 실행은 `bash run.sh` 한 줄 — README_APP 에는 그 한 줄만(설치 · 실행 명령을 따로 늘어놓지 않는다)

## 1. 화면에 긴 설명문을 넣지 않는다
- 안내문을 늘어놓지 않는다. 상세 설명은 툴팁이나 README_APP.md 로. 화면은 단순하게
- 예방: «AI 가 만든 프로그램» 티가 나고 보기에도 나쁘다

## 2. 화면 문구는 건조한 시스템 메시지체
- 친근하거나 AI 같은 말투 금지
- 예: «앗! 연결에 실패했어요. 다시 시도해 볼까요?»(✗) / «API 연결 실패 (api.example.com:443 · timeout 10초)»(✓)

## 3. 버튼 · 글자가 잘리면 안 된다
- 잘리면 요소 속성을 바꿔서라도 안 잘리게 한다. 늘리면 다른 게 잘리는 연쇄일 때만 묻는다
- 길이를 모르는 글(로그 등)은 잘림 대신 자동 줄바꿈

## 4. 외부 연동은 연결 상태 표시등
- 시작하자마자 API · DB 연결 상태를 확인해 표시한다. 가능하면 자동 연결
- 예방: 연결이 끊긴 줄 모르고 빈 화면 · 옛 데이터를 본다

## 5. 고치기 전에 연동 목록
- 같은 데이터를 그리는 곳 · 같은 계산을 쓰는 경로 · 같은 표시 항목 · 같은 규약(단위 · 색 · 순서)을 읽는 곳을 grep 으로 찾아 목록을 만든 뒤 함께 고친다
- 예방: 한 화면만 고치고 나머지 화면은 옛 동작으로 남는다

## 6. 함께 고친 것을 보고
- 무엇을 함께 고쳤는지 · 안 고친 것과 그 이유를 밝힌다 — 범위를 넓히라는 게 아니라 빠뜨리지 말라는 것

## 7. 색 · 글꼴은 토큰만
- 색 · 글꼴은 src/ui/theme.py 의 이름(ACCENT · OK · NG · WAIT · BG_* · TEXT*)으로만 쓴다. 코드에 색 값을 직접 적지 않는다
- 상태 색: OK · NG · 대기(WAIT) 셋. 같은 상태는 표 · 그래프 · 배지에서 같은 색
- 예방: 화면마다 초록 · 빨강이 조금씩 달라 상태를 잘못 읽는다
